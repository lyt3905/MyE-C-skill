# 情报字段定义

精抽阶段（由 agent 完成）必须输出符合本结构的 JSON。生成简报前用
`build_digest.py --validate-only` 校验。

## 顶层结构

```json
{
  "date": "2026-09-12",
  "generated_at": "2026-09-12 10:55",
  "source_note": "从 N 条候选微博中提取",
  "items": [ /* 情报条目数组 */ ]
}
```

## 条目字段

| 字段 | 必填 | 类型 | 说明 |
|---|---|---|---|
| `post_id` | 否 | string | 原微博 id，用于回溯与去重；与 `url` 至少填一个 |
| `blogger` | 是 | string | 发布账号昵称（转发时填**原博作者**，见下方原则 2） |
| `posted_at` | 否 | string | `YYYY-MM-DD HH:MM` |
| `url` | 否 | string | 原博链接；与 `post_id` 至少填一个 |
| `intel_type` | 是 | string | 见下方枚举，只能取这些值 |
| `brand` | 否 | string | 厂商，用通行中文名（万代、寿屋、Threezero） |
| `ip` | 否 | string | 作品 / IP |
| `character` | 否 | string | 角色或机体名 |
| `line` | 否 | string | 产品线（SS86、MP、S.H.Figuarts） |
| `scale` | 否 | string | 比例或尺寸，如 `1/6 · 全高约 30cm` |
| `price` | 否 | string | 原样保留币种，如 `7,700 円（含税）`。**有价格就必须填**——简报会打 💰 标记并进入「有价格」筛选 |
| `preorder_date` | 否 | string | **预售 / 开订 / 预约的开始时间**（不是发售日），如 `2026-11-01 10:00`、`2026-10-30 起`。简报打 ⏰ 标记 |
| `release_date` | 否 | string | **发售 / 出货 / 到货时间**。尽量精确，原文怎么写就怎么记：`2027年2月下旬`、`2026年9月3日`、`2027Q1` 均可；只知年份就写年份。简报打 📅 标记 |
| `channel` | 否 | string | 预定 / 发售渠道 |
| `summary` | 是 | string | 一句话说清是什么情报，不评价 |
| `relevance` | 是 | string | `高` / `中` / `低` |
| `relevance_reason` | 否 | string | `高` 时建议填写，说明为何与选品相关 |
| `also_reposted_by` | 否 | array | 仅在转发被合并时出现，列出也转发了同一原博的账号；可写进 `summary` 末尾 |
| `tags` | 否 | array | 自由标签 |
| `images` | 否 | array | 配图原图 URL 列表。**不用手写**，由 `attach_media.py` 自动回填 |
| `image_source` | 否 | string | `self`（本条配图）或 `retweeted`（取自转发原博的图），由脚本写入 |

> ⚠️ 字段名必须用上面这套。曾出现把 `ip` 误打成 `iv` 的情况——简报会把未知字段静默忽略，
> 不会报错，但该字段就丢了。写完建议先跑一次 `--validate-only`。

## 配图字段（`images` / `image_source`）

**不要手工填这两个字段**，跑一次 `attach_media.py` 自动生成：

```bash
"$PY" scripts/attach_media.py --input data/intel-YYYY-MM-DD.json --download
```

脚本从本地采集库（`data/candidates-*.json` + `data/wb_state.sqlite`）离线匹配微博原文取图，
顺序是「本条 `pics` → 转发原博 `pics`」，并写入 `image_source` 标明来源。

匹配同时做**一致性校验**：url 命中的那条微博，博主与时间必须和情报条对得上。
对不上说明 `url` 抄错了（历史上出现过 12 条指向别人微博），脚本会改用 `blogger+posted_at`
定位，并在输出里列「来源存疑」清单。看到提示务必核对并回写正确 `url`，否则会把别人的图
贴到本条情报上。

## 可下单标记（💰 / ⏰ / 📅）

简报要能一眼看出「哪款已经能下单、多少钱、什么时候」，所以三个字段各管一段，**不要混用**：

| 字段 | 标记 | 装什么 | 例子 |
|---|---|---|---|
| `price` | 💰 | 价格，原样带币种 | `138 元`、`7,700 円（含税）`、`US$89.99` |
| `preorder_date` | ⏰ | 预售 / 开订 / 预约**开始**时间 | `2026-11-01 10:00`、`10月30日 12:00 开订` |
| `release_date` | 📅 | 发售 / 出货 / 到货时间 | `2027年5月下旬`、`2026-10-30 发售` |

- 同一款既有开订日又有发售日时，**两个字段都写**（例：`preorder_date=2026-11-01`、`release_date=2027年5月`）
- 只有「待定 / 未定 / ???」这类占位词 → 留空，脚本按「没有」处理（会被 `_filled()` 过滤）
- 生产端：`build_digest.py` 用这三个字段给卡片打标、给筛选条计数；`assemble_intel.py` 的
  `ALLOWED` 必须包含 `preorder_date`，否则脚本会拦下这个字段
- 缺字段的后果不是报错，而是**这条情报在「💰 有价格 / ⏰ 有预售时间」筛选里看不见**

## intel_type 枚举

| 值 | 含义 |
|---|---|
| `新品公布` | 首次公开、官图放出、灰模亮相 |
| `开订` | 开启预定 / 预约 / 受注 |
| `发售` | 正式发售、上市、到货 |
| `再版` | 再版、复刻、复产 |
| `延期` | 延期、推迟、砍单、取消 |
| `展会` | 展会现场情报、会场限定 |
| `实物测评` | 实物图、开箱、评测 |
| `促销` | 折扣、特价、清仓 |
| `其他` | 无法归类 |

## relevance 判定口径

面向 62 店（Morph Toys Store，主营变形玩具 / 可动人偶）的选品视角：

- **高**：与变形金刚或现有主营产品线直接相关（SS86 / MP / MPM / JCS / DLX / 合金模型等），且信息包含可行动要素（开订、发售时间、价格、渠道）
- **中**：属动漫手办 / 可动人偶范畴但非主营 IP，可作品类拓展参考
- **低**：可动人偶但客群或品类重合度低（特摄、真人影视周边等）

## 精抽原则

1. **只抽原文有的信息**，不要推测价格或发售日；缺失就留空，简报会显示为 `—`
2. **转发要按「情报主体」归因**：
   - 采集数据里 `retweeted` 只有 post_id / author / text / pics，**没有原博链接与时间**，
     因此 `blogger` / `url` **保留自动填充**（指向捕获到的转发帖），不要手写 override——
     否则配图脚本会报「来源存疑」。
   - 原博作者写进 `summary`（如「原博 @XXX 公布…」），点开链接即见原博。
   - 转发者自己加的评论才是情报（如实测心得）时同样适用：`blogger` 即转发者（自动填充），
     `summary` 写转发者观点。
3. **一条微博含多个产品时拆成多条**，各自带同一 `post_id` / `url`，不要合并成含糊的一条
4. **纯宣传口号、无具体信息的不要输出**（如"敬请期待""即将公布"却没给任何型号或时间）
5. **社区活动帖不算情报**：抽奖、生日会、创作赛、直播预告等，即使提到产品名也跳过
6. 人民币用 `¥`，日元用 `円`，美元用 `$`，与原文保持一致
7. `relevance` 宁严勿宽——把不确定的降一档，高相关只留给真正能行动的线索
