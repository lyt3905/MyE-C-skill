# 本地商品图片助手

在开发目录双击 `gui.cmd`，或执行 `.\run.cmd ui`。已安装 wheel 时使用 `myec-automation ui`。界面使用 Python Tkinter 和现有 Pillow；当前 Windows 环境已确认 Tk 8.6 可用。没有安装 Tcl/Tk 的 Python 仍可使用 CLI，但不能启动界面。

可显式指定独立目录，不依赖启动位置：

```powershell
myec-automation ui --config-dir D:\MyConfig --data-root D:\MyJobs
```

## 连接与配置

“创建缺失配置”复用 configure init，保留已有文件。“重新加载”读取本地后台地址、账号、密码和模型网关；密码输入隐藏。

“保存本地连接配置”只更新站点连接和网关地址，保留模型参数，不修改动作授权和图片权利。若文件在界面加载后被其他程序修改，则拒绝覆盖，要求重新加载。密码按既有协议保存在本地 site.local.json，不代表加密存储；这些配置不进入 Git。

模型密钥只保存在界面会话内，传给本次启动的 CLI 子进程，不写入配置文件，也不修改其他进程的环境变量。关闭界面后需重新填写，或在启动它的环境中提供 VLM_API_KEY。

“离线检查”复用 configure check，不登录后台、不验证密钥有效性、不发起网络请求。通过只说明本地配置齐备，不能证明线上连接、模型准确率或商品整改成功。

## 任务与进度

可选择同照片替换、边框删除、局部修复、合格保留四种模拟场景。按钮委托现有 Fake CLI，界面保持响应；进度条表示仍在运行，不伪造完成百分比。已有 Job 状态直接读取状态文件，保留暂缓、未知、部分完成和错误含义。

结束后在任务列表中选择 Job，可查看证据目录、Fake 保存/上传和独立回读次数。界面不重跑旧 Job，不提供线上执行、删除、回滚或后台服务启用按钮。

“选择任务数据目录”用于查看自己独立软件的数据根（其下包含 jobs/）。原 Skill 历史 Job、凭据和授权不会自动导入。正在运行任务时先等待它结束，再切换目录或关闭窗口。

## 图片对比

在任务页选择有图片处理记录的任务，再切换“图片对比”。原图和已有干净版本/候选图从本地 Job 证据读取，校验记录中的 SHA 后展示，不下载图片，不改写原始证据。整图删除没有处理后图片；无候选或未完成记录保持空缺说明，不冒充已处理成功。

本阶段 Tk 控件和 Fake 子进程测试已验证配置页、任务完成、历史选择及图片加载。系统桌面锁定时，原生窗口实际点击和像素布局检查无法完成；该限制在本阶段验收报告中明确保留，未尝试绕过 Windows 登录。

## 真实验收

真实读取、DeepSeek 调用、上传/保存仍按 docs/real-validation-proposal.md 分别授权；GUI 不会因为填了账号或选择了 Job 就自动执行真实操作。外部重绘服务尚未配置。当前界面不是生产验收通过的声明。
