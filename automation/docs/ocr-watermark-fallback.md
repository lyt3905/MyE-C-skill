# 去水印的OCR备选流程

0.2.38默认启用。正常商品入口仍先使用现有去水印方案，首轮通过不运行OCR。首轮无法形成可执行掩膜，或实际候选质量复核未通过时，第二轮改用本地OCR编号和DeepSeek选择编号，再使用已有精细字形匹配，从原图重新生成候选。

## 两轮共享上限

默认REMOVE_TEXT最多占两个本地尝试位置：首轮现有方案，第二轮OCR备选。第二轮不叠加首轮的Mask，不读取首轮损坏像素，不额外追加旧残留补修或外部重绘。首轮尚未生成候选就失败，也会消耗其尝试位置。OCR自身固定三遍检测，每组最多八个样本、每样本三种留边；不是不断询问模型直到通过。

OCR编号选择最多一次，沿用当前DeepSeek模型、配置和同一客户端/账本；备选候选生成后使用已有完整质量复核，再最多一次模型调用。模型分数仅记录，不作业务放行门槛。单处水印可使用一个已定位样本；重复组需要证明重复匹配。没有可靠字形时不会退回大矩形。

OCR只报告文字/位置，DeepSeek选择同组删除、保留、不确定编号及漏检内容；编号必须完整、唯一且来自实际检测。原V2审核目的、KEEP文字及保护标注保持。选择与此前明确命名的保护文字冲突时拒绝（例如已标为保留的JEZZY），不把“覆盖保护区的水印”和“保护文字本身”混为一谈。该字面一致性检查不代替模型语义判断；原始标注没有明确文本名称时仍须依靠初审语义与实际质量复核。

## 仍然执行的条件

授权、图片SHA、原始观察绑定、有效坐标、总Mask上限、透明通道和Mask外像素保持不变；授权/源文件/语义契约错误不能借OCR重试绕过。保护区重叠按既有本地试修配置处理。第二轮失败、弃权、不确定编号、格式错误、OCR不可用或无法形成字形均转待复核，不能上传失败候选。

OCR检测、编号图、模型原始回复、选择结果、样本匹配证明、派生执行观察及manifest写入该任务v2_candidates/.../1/ocr-fallback/。文件及原图/观察/执行哈希绑定到既有计划和发布校验，缺失或篡改拒绝放行。编号选择是定位辅助证据，不是新的业务动作Schema，也不能凭合法JSON直接获得擦除权限。

## 配置

使用原有image-options文件，在watermark_processing中设置：

```json
{
  "watermark_processing": {
    "ocr_fallback": true
  }
}
```

未填写默认为true；显式false恢复旧的残留补修/替代算法及显式外部重绘分支。原有外部重绘并未成为OCR失败后的第三轮。图片初始动作本来是AI_REGENERATE时不属于本备选流程。

RapidOCR及其ONNX运行依赖已加入正常安装依赖，使用其随包模型，不依赖原Skill。已安装旧版的环境需重新安装/更新automation项目以补齐依赖。没有调用旧OCR语义分类器，没有修改既有视觉业务Schema。

## 验证范围

完整Fake主链覆盖首轮掩膜失败、实际质量失败、备选通过后上传保存及独立回读、第二轮失败零上传、两轮原图像素一致、首轮通过不启用OCR、显式关闭、授权拒绝及证据篡改。安装隔离测试禁止读取原Skill和开发源码。

当前本地验证另对五张冻结真实图运行新OCR和当前适配器，复用此前模型编号选择，未新增真实模型调用。三张候选与此前通过真实复核的候选字节一致，但不记为新的真实模型复核；另外两张明确待复核。具体统计与最终回归见reports/ocr-fallback-integration-report.md。
