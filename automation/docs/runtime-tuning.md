用户本轮要求：保留思考、降低推理强度、只展示最终JSON；图片下载降速，成功缓存保留、只补失败项；最多同时审核两张图片。

## 模型配置

local/model.local.json 已设置 reasoning_effort=low、image_concurrency=2。输出上限仍8192、retries仍0，模型仍只DeepSeek。模型思考没有被关闭；low参数会随请求发送，但真实网关是否遵守/能否解决主图1截断，本轮未进行新增真实调用，不能声称已真实验收。

image_concurrency只允许1或2，写入每个新Job的冻结配置和指纹。V2的RECORD_ONLY审核按此值调度，同一时刻最多两个各含一张原图的请求；独立记账、独立处理异常，结果仍按原图顺序关联。严格受控历史预算继续串行，不改旧策略。旧配置未写该字段时保留串行兼容。

## 展示最终JSON

```powershell
.\run.cmd results JOB_你的任务ID --root D:\你的Job根目录
```

该本地命令只返回各图最终模型JSON、程序判定、独立策略修正和原因码；模型原判与程序修正分别展示，不包含reasoning_content或原始响应。没有有效最终答案的图，final_json=null、decision=REVIEW，不从思考文字拼凑判断。原始响应继续保存在原有metrics及SQLite账本中；本命令不改历史文件。GUI按用户此前选择仍留到下一轮，未来界面可以使用同一结果接口。

## 下载限速与缓存

默认一个下载线程，同域名网络请求启动至少间隔1秒。命中成功缓存时不等待、不请求；缓存有SHA侧文件，字节损坏时不会当作成功复用。HTTP429保存http_status和数字Retry-After，单次下载不自动重试，不保证服务端立即解除限流。

正式网络采集将成功缓存放在Job根目录的image-download-cache；每个Job仍保存自己的audit_images证据副本。成功缓存按显式reuse_successful模式保留，不因普通TTL到期就重新下载；force或普通TTL调用的既有语义不变。失败项不写成功缓存，新任务显式运行时只请求缺失/失败/损坏项。采集阶段不得用可变共享缓存路径替代Job原图证据。

旧任务的成功图片可显式离线导入缓存，按原封存清单和内容SHA核验，不导入旧授权、账本或模型结果，也不改旧Job：

```powershell
.\run.cmd cache-images JOB_你的任务ID --root D:\你的Job根目录
```

可选--cache-root指定目的缓存目录；后续正式采集默认使用该Job根目录的image-download-cache。
