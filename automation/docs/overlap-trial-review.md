# 先本地试修，再审核实际保护效果

2026-11-18，0.2.37。正常商品流程无需Agent逐张接管。现有process/run_automatic继续调用同一套DeepSeek初审、remove_text、质量复核、受限保存和独立回读。

## 默认流程

1. DeepSeek给出去水印动作、实例/样本和需要保留的区域。原始回复与保护标注不改写。
2. 程序优先选择已有精细字形路径，缺少可靠样本时保留有界区域方案。
3. 合法水印掩膜与保护区域重叠时，允许生成一个独立本地候选。旧10%印刷比例及重叠作为试修诊断记录；不因预测可能损坏而直接拒绝。原图、alpha和掩膜外像素继续保留。
4. 将候选、原图、实际掩膜、原始保护标注及实际像素变化交给DeepSeek复核。受影响保护区域增加青色标注图PROTECTED_REGIONS，仅作定位；它不是修复结果。程序同时记录绑定Source/Candidate/Mask的protected_region_comparison。
5. 只有完整有效的五项质量检查全部通过、残留检查通过时，才产生可保存的候选资产。明确商品/印刷损坏、弃权、格式无效或无法确认不放行。适合的残留沿用最多一次补修，始终取原图并合并Mask；两次仍不通过转待复核。

保护标注现在作为实际比较目标，既不会被删除，也不会被偷偷改成“允许损坏”。试修不是质量PASS；数字变化比例不是文字/结构是否损坏的结论。明确把厂家/商品印刷本身标为REMOVE_TEXT的语义矛盾仍拒绝，不能借试修绕过。

## 仍然执行的检查

修改授权、完整现有Schema/业务一致性、图片SHA、合法坐标、总Mask25%或更小自定义上限、原图/alpha/Mask外像素、实际候选质量、保存范围及独立回读保持。保护区重叠和10%旧印刷重建比例只在允许本地试修时延后；严格模式保留原检查。

试修候选的发布证明必须有PASS的实际保护复核，以及与原始保护标注、实际原图/候选/Mask相符的对比记录。对比文件放在quality_evidence/protection_comparisons/，哈希纳入原执行计划；丢失、改动或不同来源的记录不能批准资产。

## 配置与兼容

正常V2产品入口remove_text默认开启；新的image-options示例也显式开启：

```json
{
  "watermark_processing": {
    "protection_overlap_trial": true
  }
}
```

设为false可恢复旧的预先保护拦截及有限印刷重建策略。原有covered_print_policy控制该严格分支，不负责试修后的质量PASS。低层mask_for默认仍严格；独立调用process_watermarks的调用者需显式传入policy.protection_overlap_trial=true，避免改变已有低层调用的含义。

三次初审结构重试、RECORD_ONLY、同原图替换优先、SKU/正文引用同步、标题和非图片字段保护继续沿用。命令入口、模型和密钥配置不变。

## 本轮验证边界

冻结此前仍待复核的7张真实图片和已验证观测，在当前默认入口均生成本地候选；所有原图和历史文件哈希不变，掩膜外像素检查通过。这仅验证候选生成；本轮未新增真实DeepSeek复核或线上操作，不把7个候选称作7张修复成功。

新流程通过完整Fake主链验证质量通过后保存、实际损坏/未知零上传、比较证明篡改拒绝，以及一次补修上限。最终完整测试、安装隔离和候选证据见本地reports/overlap-trial-review-20261118/及验收报告。
