# 通用文字水印处理

2026-11-17，软件 0.2.33。复用既有 `REMOVE_TEXT`、OpenCV、LaMa、执行计划和修复后质量审核，支持三类输入：单处文字、多处文字、大面积半透明文字。不针对固定店铺、字词、字体或颜色。

| 场景 | 定位与掩膜 | 执行 |
|---|---|---|
| 单处文字 | 自动检查 AI 指定区域能否作为字形样本；无需第二份水印或人工选样本 | 简单小区域按原路由使用 OpenCV，其余使用 LaMa |
| 多处文字 | 每处独立坐标；可靠的同组样本可以共享，不同文字组分别处理 | 局部处理后融合 |
| 大面积半透明文字 | 优先提取稀疏文字笔画；区域过大时拆分为带上下文的重叠块 | 多次局部 LaMa，按边缘权重融合，最后整图审核 |

AI 决定文字是否为附加水印、是否去除、`content_type=TEXT`、各实例坐标和 `group_id`。程序不识读店铺名称，也不重新判断文字归属。自动选样本只使用 AI 已指定的同组文字区域，最多检查八个候选；使用原有均匀边界、笔画几何和模板匹配规则。可以检查同组其它区域是否支持该样本，避免把背景条纹当作共同字形。尺寸和角度不同的实例也可使用自己的样本。

不能取得可靠字形样本时，记录失败原因，回到 AI 的原始有界 `REGION` 方案生成候选，不宣称已经得到精细掩膜。AI 定位错误、混入商品或底图纹理复杂时，字形提取和修复效果仍可能不理想；最终由实际结果复核决定。无法恢复的被遮挡信息不能保证还原。

大范围搜索框不再直接等同于整框擦除，也不再仅因单个 ROI 大就拒绝：先看真实掩膜，再分块。每块仍满足 `max_roi_area`，带上下文和重叠；只融合总掩膜内部的预测，保留掩膜外 RGBA 和原图。上下文过大而无法满足指定面积、实际掩膜超过总面积限制等情况会明确报告。原 `max_mask_area` 默认及上限 25% 不变，指实际掩膜像素，不是文字外接框面积。

自动字形掩膜在原图周围确实为均匀背景的局部区域，会复用已存在的背景清理步骤，消除 LaMa 淡影；复杂背景不会强行铺成纯色。该步骤也仅修改字形掩膜内部。

原始模型 JSON、派生 `mask_plans`、最终执行几何、样本失败原因和每块修复记录分别保留。执行计划不伪装成原始模型输出。实际采用的几何交给原有修复后审核，原回复不改写；旧 Jobs/缓存/账本不重置。

配置在既有 `local/image-options.local.json` 的 `watermark_processing` 内：

```json
{
  "auto_text_masks": true,
  "tile_large_regions": true,
  "tile_overlap_pixels": 32,
  "context_pixels": 16,
  "max_roi_area": 0.45
}
```

三个新增选项默认即启用以上行为；`auto_text_masks=false` 可保留原始明确区域方案，`tile_large_regions=false` 可保留原有超限 ROI 拒绝行为。配置随 Job 固定。没有新建业务 Schema，V2 字段/枚举不变；新增的只是现有模块内部配置，已与 image-options 校验同步。

正常程序入口不变，不需要另跑新 Runner。单独调用仍使用：

```python
from mye_c_automation.watermark_processing import process_watermarks
result = process_watermarks(request, new_output_directory, lama=existing_lama)
```

`PROCESSED / PENDING_AI_REVIEW` 仅表示候选已生成。必须再通过现有 DeepSeek 原图对比复核，才能进入已有上传/保存流程。授权、SHA、精确原厂印刷保护、实际面积检查、有限补修和独立回读仍有效。没有自动把所有原厂横幅改成允许重建；此前专门授权的局部 `PRINT_RESTORE` 继续按原规则执行。

本轮验证材料在本地 `reports/general-text-watermarks-20261117/`，包括三类合成样例的真实本地 LaMa 输出、测试与安装证据。合成样例和模拟 AI 区域不等于真实图片的模型定位验收，也不等于线上生产验收。
