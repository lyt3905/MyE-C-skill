# MyE-C Automation 当前完整工作流

核对日期：2026-11-18；本地软件：0.2.34。本说明按当前 `process` 调用链编写，旧 README/报告中的版本号和历史参数不代表当前配置。软件独立运行，不依赖原 Skill，也不需要 Agent 逐阶段衔接。

## 入口与当前运行条件

在 `D:\GitHub\MyE-C-skill\automation` 中运行。只审核：

```powershell
.\run.cmd process https://39.107.244.239/products/商品ID --audit-only
```

正式处理（在有效授权配置内会真实上传/保存）：

```powershell
.\run.cmd process https://39.107.244.239/products/商品ID
```

`--audit-only` 会读取线上数据并调用真实模型，但不执行超过六张主图的预删除、图片修复、上传或商品保存。标题功能开启时可生成标题建议。`fake --scenario repair` 才是完全离线的模拟流程。

当前公共配置：DeepSeek `deepseek-v4.1-flash`、低强度思考、输出上限100000、独立图片审核并发10；下载同域名请求间隔至少1秒，失败最多额外重试3次（最多4次尝试），成功缓存复用。模型思考/原始响应留档，用户结果展示最终 JSON。API输出上限不是每次固定用量。

公共自动执行总开关 `enabled=false`，店铺白名单为7。公共 `TITLE_REWRITE` 默认开启，图片修改默认按用户授权处理；商品专用策略仍可明确调整。指定商品存在 `local/products/商品ID/automation.local.json` 或 `image-options.local.json` 时优先用其对应文件；它们不是对公共文件逐字段自动合并。实际可执行范围看最终选中的策略。

## 配置

| 文件 | 作用 |
|---|---|
| `local/site.local.json` | 后台地址和登录配置 |
| `local/model.local.json` | 模型、网关、推理强度、输出上限、审核并发 |
| `local/model-key.local.json` / 环境变量 | 模型密钥；环境变量优先 |
| `local/automation.local.json` | 执行总开关、店铺/商品范围、动作权限、七图规则、可选标题策略 |

配置检查可运行 `run.cmd configure check` 或 `run.cmd doctor --config-dir .\local`，只做离线检查，不登录或请求模型。已有配置不覆盖。模型权重、账号和密钥不从原 Skill 自动寻找。

## 1. 校验入口与绑定任务

程序检查商品链接是否与配置的 HTTPS 后台一致，解析商品ID。自动执行模式先检查总开关、商品范围和店铺限制，再登录读取当前店铺；不偷偷切换店铺。发现身份或范围不符就结束。

为任务建立独立 Job，保存执行模式、配置、Prompt/Schema/程序绑定、原始商品快照及状态摘要。预算账本、模型原始响应、缓存、执行日志和报告均有独立证据。旧 Job 的授权/预算不复制成新授权。

## 2. 默认主图超过六张时的预处理

默认启用预处理（保留兼容配置名 `trim_seven_main_before_audit`）。仅正式执行且允许DELETE时生效：主图超过6张，选原第一张作为唯一删除目标，同步移除它在主图/详情/SKU池中的同URL引用、正文商品图片节点，并将SKU行匹配的图片字段清为null。SKU行、规格、价格等不删不改；正文文字和footer保留。

每次只选一个目标，不循环删到6张；8张通常变7张。后续任务通过已完成预处理的新Job证据承接这个数量，不会对普通未绑定计划放宽数量检查。若同一URL在主图重复出现，目标的重复引用也一并移除。6张及以下不执行。保存一次并独立回读确认后，建立正式审核Job；正常SKU选图可为被清空引用的SKU重新分配合格图片。没有合格替代图时保留待处理状态。

该步骤不调用模型、不上传新图片。预处理与正式整改分别留证，可能共两次保存。未知保存只回读，不重复删除或保存。图片引用按明确URL处理，不在这个计数步骤中猜测不同URL是否同一图。

## 3. 读取、下载、缓存和去重

读取主图、详情图、SKU图片池、真实SKU行图片引用，以及正文里的商品图片节点。正文文字不送入视觉审核；尾部 `shopFooter` 及其后附加内容不作为商品图清理。`images.ai`、`images.scene` 不纳入当前正式V2审核范围。

按配置限速下载；429/临时网络问题按退避规则重试，成功缓存保留，优先补缺失/失败/损坏图片。无法读取的图片明确记为未审，不以模型猜测替代。每个 Job 保留自己的原图证据，避免共享缓存被修改后污染任务。

按文件 SHA 去重：同一图片即使在多个URL、主图/详情/正文/SKU出现，也只建立一份内容审核，保留每处引用用于后续同步。不同内容不能因为看起来是同款就合并。

## 4. DeepSeek 全图初审与本地契约校验

DeepSeek 判断图片内容、包装、SKU适用性、文字归属、待去除实例和需要保护的区域。程序不再用另一套OCR/CV语义分类重新投票。型号/配色等记录性字段和所有模型置信度不作为数值放行门槛。

模型返回后检查请求完成/截断/非空、JSON解析、完整现有V2 Schema、字段类型/枚举、SHA/证据绑定、坐标以及独立业务条件。当前网关未证明强制执行JSON Schema，采用明确的JSON模式加完整本地校验；不能只因返回合法JSON就允许擦除。校验不通过则记原因、待复核，不伪造缺失字段。

主要初审动作：

| 动作 | 含义 |
|---|---|
| KEEP | 保留图片或指定文字 |
| DELETE | 按已授权规则删除相应图片引用，仍检查受影响SKU及必要包装留存 |
| REMOVE_TEXT | 生成本地去水印候选，不能直接宣布通过 |
| REVIEW | 真实目标/输入/执行条件未解决，保留原图待复核 |
| AI_REGENERATE | 单独配置与授权的外部重建路径；普通本地去水印不依赖它 |

## 5. 同一原图干净版本优先

初审后，程序在当前商品已有、已获KEEP的干净图中寻找同一照片的其他版本，用现有特征匹配和像素对齐证明同原图。不是判断“同型号/同配色/同姿势大致相似”，也不搜索外部图片。

能够证明可替换时优先 `REPLACE_TWIN`，直接复用已有URL，零新图上传，无需先擦除再做修复质量模型调用。不能证明可替换就回到原来的保留/删除/去字处理，不据此认定不是同图或该整图删除。

## 6. 去文字水印：先候选，再看实际效果

AI提供文字区域和分组，程序按当前通用模块处理：

| 场景 | 当前方式 |
|---|---|
| 单处文字 | 自动尝试从该区域提取字形，不要求有第二处重复水印 |
| 多处文字 | 每处独立坐标，可共享可靠同组参考，不把不同组文字混成一个模板 |
| 大面积半透明文字 | 优先笔画级掩膜；过大的ROI拆成带上下文的重叠块，按需调用LaMa并融合 |

无可靠样本时记录原因，回到原始有界区域试修。简单小区域可用既有OpenCV，其余按既有路由使用LaMa。原图不覆盖，只写新候选。自动字形在确实均匀背景上的淡影可以局部清理；复杂背景不强制涂平。

重叠风险只记录，不因预测“可能损坏”就拒绝尝试。修改授权、实际SHA、坐标、精确保护像素、实际掩膜/ROI面积等固定条件仍检查。没有自动授权擦除原厂文字；需要有限印刷重建时使用已明确启用的原有规则。

保留原始AI回复，另存 `mask_plans` 和实际执行几何，不把程序派生计划冒充原始模型输出。

## 7. 修复后真实质量复核

把候选、原图和实际修复范围交给DeepSeek，同一模型检查：商品结构、包装、原厂文字、附加水印是否去除、是否出现新伪影。根据当前图像实际差异判断，不因为初审风险高或采用某种方法而预测性拒绝。

全部通过才让候选进入后续计划。有明确可补修残留时，走既有有界补修再复核；结构/原厂文字损伤或无法验证的候选保留为待复核，不能无限重试或上传冒充成功。模块的 `PROCESSED/PENDING_AI_REVIEW` 只是生成候选，不能当作此阶段通过。

## 8. SKU选图和引用同步

使用保留的干净图、验证通过的修复候选或已证明可用的同原图替换图选取SKU图片。按现有规格名称区分无盒/有盒：

- 无盒SKU选择合格非盒照；有盒SKU优先合格盒照。
- 没有合格盒照时，已有一对无盒/有盒规格可以分别使用两张不同内容的合格非盒照，不伪称第二张展示了盒子。
- 图片不足、规格复杂或SKU无法可靠绑定时报告待处理，不新建SKU、不改购买规格、名称、价格或 `originalBox`。
- 同一图片的主图、详情、正文商品图片和SKU引用按内容组同步；不能只换主图、让SKU继续引用旧水印图。每条SKU仍是一个图片URL。

## 9. 默认标题改写

新配置及当前本地有效策略默认启用 `TITLE_REWRITE`；明确关闭时才跳过。使用现有DeepSeek标题流程。输入原始标题、现有英文标题、型号资料、SKU名称/型号和明确确认的事实，正文/价格/后台凭据不进入标题请求。

按现有店铺前后缀、长度和业务规则校验；不能生成合规标题时保留原题并记原因，不把图片处理一并伪装为失败或成功。标题请求的重试设置与图片审核独立。合格标题与图片整改进入同一个正式保存计划；涉及站点标题翻译时按现有一次翻译及回读流程执行。

## 10. 计划、预演与受限执行

程序汇总删除/替换/新候选/SKU/可选标题，生成有源状态和候选SHA绑定的计划；同时保留待复核清单。保存前重新读取并比较线上状态，模拟修改，核对动作权限、引用和受保护字段。商品已被他人修改等前置条件不符时，不强行覆盖。

执行时只上传真正需要的新候选，内容相同的候选避免重复上传；已有URL的同原图替换不上传。再按计划受限保存商品。价格、库存、运费、重量、预售/状态、购买规格等非批准字段继续保护。正文商品图片引用可以按计划同步，正文文字/样式及尾部内容按既有规则保留；站点允许的顶部标题自动区例外由现有规则核对。

独立可确定项目可以完成，未确定项目如实留在清单；同一内容组或SKU绑定存在依赖时，不拆成互相矛盾的半套修改。执行账本防重复写入，保存结果未知不能盲目重发。

## 11. 新登录会话独立回读

保存接口返回成功不作为最终完成。使用新会话重新读取商品，并检查实际图片字节、主图/详情/正文图片、SKU引用、可选标题及应保护字段是否符合计划。系统自然更新时间单独记录，不拿它伪装其他业务字段变更通过。

回读不一致、图片无法读取或翻译仍在处理中，都要保留对应状态。确认实际结果后才输出完成。

## 12. 结果、报告与恢复

| 状态 | 含义 |
|---|---|
| AUTO_VERIFIED | 本任务批准处理范围完成，独立回读通过，无待复核项 |
| CLEAN | 没有需要变更的项目，仍查看验证和范围 |
| PARTIALLY_AUTO_FIXED | 部分整改已完成，仍有待复核项 |
| REVIEW_REQUIRED / CONTENT_REVIEW_REQUIRED | 语义、输入、质量或最终内容核验仍有未解决项 |
| APPLY_UNKNOWN | 保存结果未知，仅回读恢复，不重发保存 |
| TRANSLATION_PENDING | 已进入标题翻译等待状态，未宣称整件完成 |
| AUDITED | 只读审核运行结束，没有执行整改 |
| FAILED / ERROR | 配置或执行失败，查具体原因 |

输出包含 Job ID、修改和上传/保存次数、模型调用及已知用量、待复核项、独立验证、报告位置。检查 `whole_product_clean` 和待复核清单，不以进程退出0或“JSON成功”代替整件通过。费用/usage未知保留null，不伪造0。

恢复：

```powershell
.\run.cmd process https://39.107.244.239/products/商品ID --resume JOB_实际ID
.\run.cmd status JOB_实际ID
.\run.cmd results JOB_实际ID --root D:\GitHub\MyE-C-skill\automation\data\jobs
```

恢复须匹配原链接、模式和配置；已完成任务返回原结果，未知保存只检查真实结果，不重复写。下载成功缓存可复用，失败项再按规则补读。明确已保存但部分回读失败的受限续办会建立新任务并保留原证据，不重写旧账本。

默认运行数据在 `automation/data/`，任务位于 `data/jobs/JOB_.../`；也可使用 `--data-root` 指定。原图、AI原始回复/思考、派生计划、掩膜、候选、质量结果、执行回执及回读证据留档。日常查看最终报告/JSON即可，必要时再查原始材料。
