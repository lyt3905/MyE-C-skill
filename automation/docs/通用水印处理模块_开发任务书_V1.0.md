# Watermark Processing Module V1.0

## 1. 项目基本信息

  项目       内容
  ---------- --------------------------------------------
  所属项目   MyE-C-skill
  软件主体   `automation/`
  模块       Watermark Processing Module
  版本       V1.0
  业务基线   `68e168f1a08c6338cb0964dffbd021bb5e484556`
  技术栈     Python、现有 DeepSeek Vision、OpenCV、LaMa

## 2. 项目背景与目标

在现有 MyE-C V2
图片审核与整改架构中，建设一个通用、独立、可复用的水印处理模块。

模块不针对 GCC Model Store
或任何固定店铺、品牌、文字、字体、颜色、角度开发专用逻辑。不同店铺名称和水印样式只是测试样本。

核心原则：

**AI 负责理解图片和识别水印；Watermark Processing Module
负责执行修复；主工作流负责管理业务、授权、质量复核和商品更新。**

目标能力：

1.  接收 AI Vision 已识别的水印区域。
2.  支持单个和多个水印区域。
3.  支持不同排列、角度、文字、图形和透明度。
4.  管理水印实例、分组及局部修复区域。
5.  生成精准 Mask。
6.  根据区域特征选择 OpenCV 或 LaMa。
7.  支持多区域分批修复与结果融合。
8.  保护商品主体、型号、Logo、印刷和包装信息。
9.  输出修复结果、Mask、SHA 和完整执行记录。
10. 执行确定性检查，并返回现有 DeepSeek Vision 复核。
11. 通过现有 `REMOVE_TEXT` 路径接入商品整改流程。

## 3. 模块在主流程中的位置

``` text
图片采集与 SHA256 去重
    ↓
现有 DeepSeek Vision 图片审核
    ↓
AI 输出图片动作
    ↓
REMOVE_TEXT
    ↓
授权门禁
    ↓
Watermark Processing Module
    ├── 输入与坐标校验
    ├── 水印区域管理
    ├── Mask 生成
    ├── OpenCV / LaMa 修复
    └── 确定性质量检查
    ↓
现有 DeepSeek Vision 质量复核
    ↓
PASS / REVIEW / FAIL
    ↓
返回现有商品整改计划
```

`KEEP`、`DELETE`、`AI_REGENERATE`、`REVIEW`
仍由现有工作流处理。模块不得直接执行线上商品上传、保存或回读，不得绕过现有
Plan 和执行器。

## 4. 职责边界

### 4.1 AI Vision

使用现有 DeepSeek Vision 客户端，负责：

-   判断是否存在外加水印。
-   区分店铺水印、厂家
    Logo、商品自身印刷、包装印刷、创作者署名和未知文字。
-   判断水印是否重复及其视觉排列类型。
-   输出每个水印的 bbox / polygon。
-   输出水印分组信息。
-   判断水印与商品主体、保护区域的重叠情况。
-   输出需要保护的商品区域。
-   对修复前后图片进行视觉复核。

AI 不得输出自由代码、Shell 命令或未经 Schema 约束的执行参数。AI
不能仅凭视觉判断版权或授权状态。

### 4.2 Watermark Processing Module

负责：

-   解析并校验 AI 结构化结果。
-   校验输入图片 SHA、尺寸和坐标。
-   管理水印实例与分组。
-   规划局部 ROI 和上下文范围。
-   生成、扩张、合并和可视化 Mask。
-   执行保护区域约束。
-   选择并调用 OpenCV / LaMa。
-   保存新图片、Mask 和处理证据。
-   执行确定性质量检查。
-   返回标准化处理结果。

模块不得重新判断文字是不是水印，不得自行改变 AI
语义结论，不得依赖店铺名称、品牌、SKU 或特定商品类型。

### 4.3 主工作流

负责 AI 调用、素材授权检查、模块调用、AI
质量复核、Job、预算、日志、Plan、上传、保存和独立回读。模块不创建第二套主工作流。

## 5. 通用水印范围

### 5.1 排列方式

-   `SINGLE`：单个水印。
-   `REPEATED`：多个重复水印。
-   `DIAGONAL`：斜向排列。
-   `HORIZONTAL`：横向排列。
-   `VERTICAL`：纵向排列。
-   `GRID`：网格平铺。
-   `SCATTERED`：不规则分散。
-   `MIXED`：多种排列混合。

### 5.2 视觉内容

-   `TEXT`：文字。
-   `GRAPHIC`：图形。
-   `LOGO`：Logo。
-   `TEXT_AND_GRAPHIC`：文字与图形组合。

具体语义由 AI Vision 提供，程序不得用 OCR、模板匹配或传统 CV
分类器重新识别。

### 5.3 视觉变化

必须兼容不同文字内容、字体、字号、颜色、透明度、角度、尺寸、间距、密度、背景，以及水印跨越商品和背景、多组水印同时出现等情况。

不得写死 GCC、店铺名称、固定文字、固定颜色、固定字体或固定角度。

## 6. 内部组件设计

### 6.1 `WatermarkInputParser`

解析和校验： - 输入 Schema 及版本。 - 图片路径或字节。 - 图片宽高及
SHA256。 - AI 决策与水印区域。 - 授权状态。 - 商品保护区域。

关键字段缺失、SHA 不匹配、坐标无效时拒绝处理。

### 6.2 `WatermarkRegionManager`

负责： - 管理多个水印实例。 - 管理 AI 提供的 `group_id`。 -
保留每个实例的独立坐标。 -
根据分组信息和确定性几何关系分析区域相邻性。 -
合并适合一起修复的相邻区域。 - 为每组规划局部 ROI 和上下文。 -
避免不相邻区域被合并为巨大区域。

不得通过 OCR 或模板匹配补充水印语义识别。

### 6.3 `WatermarkMaskBuilder`

负责： - bbox / polygon 坐标转换。 - 多区域 Mask 生成。 - Mask
边缘适度膨胀。 - 保护区域约束。 - 面积与边界检查。 - Mask 可视化和保存。

统一采用左上角原点、0.0--1.0 归一化坐标。最终 Mask
尺寸必须与原图一致。保护区域发生高风险冲突、Mask
超限或坐标错误时停止并转 REVIEW。

### 6.4 `RepairRouter`

统一选择修复算法：

  算法             适用情况
  ---------------- --------------------------------
  `OPENCV_TELEA`   小面积、简单背景
  `OPENCV_NS`      Telea 备用方案
  `LAMA_INPAINT`   较大面积、复杂纹理、半透明覆盖

选择依据包括 Mask 面积、形状、ROI 大小、AI
提供的主体重叠信息和可配置策略。不得对所有图片无差别调用 LaMa。

### 6.5 `InpaintingEngine`

提供统一修复接口，包含 OpenCV Telea、OpenCV Navier-Stokes 和 LaMa
Adapter。

优先复用已安装的 LaMa。必须验证其在独立 `automation/`
环境中的模型加载、推理和输出。模型未加载或推理失败时不得静默返回原图并标记成功。

不安装 MAT 和 Stable Diffusion Inpainting。

### 6.6 `WatermarkQualityChecker`

执行确定性检查： - 输出文件可解码。 - 输出尺寸和格式符合要求。 - 输出
SHA 正确。 - Mask 文件存在且有效。 - Mask 外区域无非预期变化。 -
原图未被覆盖。 - 处理区域和算法记录完整。 - 修复过程没有异常。

AI 视觉复核由主工作流调用现有 DeepSeek Vision，不在模块内创建第二套 AI
客户端。

## 7. 输入与输出契约

### 7.1 输入字段

至少包含：

-   `schema_version`
-   `image_path` 或 `image_bytes`
-   `image_sha256`
-   `image_width`
-   `image_height`
-   `decision`
-   `authorization_status`
-   `watermarks`
-   `preserve_regions`

水印实例建议包含：

-   `watermark_id`
-   `group_id`
-   `kind`
-   `region_type`
-   `polygon` 或 `bbox`
-   `confidence`
-   `preserve_overlap_risk`

必须优先兼容现有 V2
Schema。确需扩展时进行版本管理，不得建立冲突的第二套业务
Schema。置信度沿用 `RECORD_ONLY`，不得另设数值放行门槛。

### 7.2 输出字段

至少包含：

-   `processing_status`
-   `quality_status`
-   `input_sha256`
-   `output_sha256`
-   `output_path`
-   `mask_paths`
-   `visualization_path`
-   `watermark_instances_total`
-   `watermark_instances_processed`
-   `algorithm_used`
-   `model_version`
-   `processing_parameters`
-   `execution_time`
-   `failure_reason`

`processing_status`： - `NOT_APPLICABLE` - `BLOCKED` - `PROCESSED` -
`FAILED`

`quality_status`： - `PENDING_AI_REVIEW` - `PASS` - `REVIEW` - `FAIL`

本地修复成功不等于最终质量审核通过。

## 8. 多水印处理规则

多个重复水印不得直接合并为一个覆盖范围很大的 Mask。

``` text
AI 返回全部水印区域
    ↓
读取各个 polygon
    ↓
按 group_id 管理
    ↓
检查空间关系
    ↓
规划独立局部 ROI
    ↓
合并适合一起处理的相邻区域
    ↓
检查保护区域
    ↓
生成局部 Mask
    ↓
执行修复
    ↓
融合回原图
```

要求： - 每个水印实例可独立追踪。 - 每个 ROI
保留周围原始像素作为上下文。 - 不相邻区域不得无条件合并。 - 单个 ROI
超过配置限制时转 REVIEW。 - 分批修复不得破坏其他尚未处理区域。 -
多区域结果必须正确融合。 - 每个区域的算法、参数和结果均可追溯。

## 9. 授权与保护规则

沿用项目 V2 规则：

-   `OWNED_OR_LICENSED`：允许进入处理门禁。
-   `RIGHTS_UNKNOWN`：不得自动擦除第三方归属标记。
-   `THIRD_PARTY_ATTRIBUTION`：不得为了隐藏来源而擦除。
-   未知普通文字不得擅自删除。
-   原厂 Logo、商品印刷、型号文字、包装印刷必须保护。
-   创作者署名遵守现有归属保护规则。

授权状态必须来自程序配置和素材来源证据，不能由 AI 猜测。

Description 不属于本模块的图片处理输入，不得改变现有 Description
处理边界。

## 10. 图片保护规则

1.  原始图片只读。
2.  所有输出写入新文件。
3.  保留原图 SHA256。
4.  每次修复生成独立结果。
5.  Mask 外区域原则上保持原像素不变。
6.  不得擅自改变商品型号、颜色、机械结构或配件数量。
7.  不得破坏包装和原厂文字。
8.  修复失败的图片不得进入上传计划。
9.  若边缘羽化或融合导致 Mask
    外像素发生变化，必须将实际影响范围纳入记录和检查。

## 11. AI 质量复核

修复后由现有 DeepSeek Vision 复核，输入包括原图、修复图、必要的 Mask
可视化图、原始 AI 观察结果和必要的商品上下文。

检查水印残留、商品主体、型号、颜色、机械结构、配件、原厂
Logo、商品印刷和修复伪影。

结果： - `PASS`：允许进入现有整改计划。 -
`FAIL_RETRYABLE`：按预设策略切换备用算法重试一次。 -
`FAIL_WATERMARK_REMAINS`：允许一次备用算法，仍失败则 REVIEW。 -
`FAIL_IDENTITY`：拒绝修复图，保留原图并转 REVIEW。 -
`FAIL_UNKNOWN`：保留原图，不上传。

禁止无限重试。

## 12. 与现有工作流集成

通过现有 `REMOVE_TEXT` 路径调用。

禁止： - 新建第三套 Workflow Runner。 - 新建重复 DeepSeek 客户端。 -
新建独立 Job 管理器。 - 新建重复预算账本。 - 新建第二套商品写入器。 -
绕过商品更新计划、保存和独立回读。

模块提供稳定 Python API，返回结构化结果，由现有工作流决定下一步。

## 13. 测试计划

### 13.1 水印排列测试

-   单个文字水印。
-   两个重复水印。
-   多个斜向重复水印。
-   多个横向重复水印。
-   纵向排列水印。
-   网格排列水印。
-   不规则排列水印。
-   多种排列方式混合。

### 13.2 水印视觉特征测试

-   不同文字内容、字体、颜色、透明度和尺寸。
-   不同倾斜角度。
-   文字和 Logo 组合。
-   重复图形水印。

### 13.3 商品保护测试

-   水印覆盖纯色背景。
-   水印覆盖复杂背景。
-   水印覆盖商品表面或机械结构。
-   水印靠近型号文字或原厂 Logo。
-   水印与包装印刷相邻。
-   商品自身文字被误判。

### 13.4 异常测试

-   AI 输出缺少水印坐标。
-   polygon 越界或无效。
-   图片 SHA 不一致。
-   Mask 面积过大。
-   LaMa 加载或推理失败。
-   OpenCV 异常。
-   修复后仍存在水印。
-   修复破坏商品结构。
-   输出图片损坏。
-   原图被意外修改。

`automation/reports/lama-environment-check.md`

输出： - `automation/reports/generic-watermark-processing-module.md` -
完整测试报告。 - 模块接口文档。 - 本地模型依赖清单。 -
修复前后对比样本。 - Mask 可视化样本。

测试状态必须区分： - `IMPLEMENTED` - `FAKE_VERIFIED` -
`REAL_MODEL_VERIFIED` - `BLOCKED` - `NOT_RUN`

## 15. 最终验收标准

1.  模块独立于商品业务逻辑。
2.  不依赖 GCC 或其他固定店铺名称。
3.  支持不同类型和排列的水印。
4.  支持多个水印区域、不同角度和不规则排列。
5.  能够生成正确 Mask。
6.  能够调用 OpenCV 和 LaMa。
7.  LaMa 在 automation 独立环境完成真实本地推理。
8.  原始图片得到保护。
9.  Mask 外区域没有非预期变化。
10. 失败能够安全回退。
11. 通过现有 AI 视觉复核。
12. 可以被现有工作流调用。
13. 不破坏现有 V2 商品审核与整改流程。
14. 原 Skill 项目完整保留。

**最终目标：建立一个可复用于任何符合输入契约的商品图片工作流的通用水印处理模块。**
