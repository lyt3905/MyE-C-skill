# 先修复候选，再审核实际效果

2026-11-17，软件 0.2.32，按用户新规则调整。

初审 DeepSeek 只依据可见内容给出动作、既有 `repair_mode` 和逐个水印的坐标，不预测去水印会不会破坏商品。明确的附加水印即使覆盖商品、背景复杂或没有干净模板，也可用精确的 `REGION` 尝试本地修复。优先复用已验证的同原图干净版本规则不变。

程序在单独的候选文件中执行既有 OpenCV/LaMa 流程；主体重叠、透明或复杂区域仍由现有路由选择 LaMa。之后 DeepSeek 对比候选与原图，核对商品结构、包装、原厂文字、水印残留和新伪影。只有实际候选通过全部检查，才具有后续上传资格；授权和独立回读等条件继续适用。残留水印仍可走已有的有限补修流程，不能无限重试或强行宣布成功。

`preserve_overlap_risk` 为兼容原 V2 Schema 和历史回复继续保留 LOW/MEDIUM/HIGH，只记录，不再单独拦截修复或构成受保护内容冲突。未新增或修改业务 Schema 字段、枚举。旧 Job 的 REVIEW 不自动改写成 REMOVE_TEXT；新提示词进入缓存键，新审核不会复用旧提示词的结论。

固定校验仍保留：修改授权、图片 SHA、字段格式、真实可执行坐标、精确原厂 Logo/商品文字保护区域、Mask/ROI 面积、后端可用性、掩膜外像素及实际质量审核。未能确定待处理对象、缺失坐标或精确保护区域冲突不能靠“先执行”绕过。这些是已有输入/执行条件，不是对修复效果的预测。

本轮只做本地实现和离线验证，不调用真实 DeepSeek、不访问或写入线上商品、不改历史响应/账本，也不自动提交或推送 Git。完整验证记录位于本地 `reports/repair-before-review-20261117/`。
