# 默认优先使用精细字形去水印

0.2.37更新：产品流程保留精细字形优先，并默认允许保护重叠本地试修；旧10%及重叠前置门禁保留在显式严格模式。原保护标注用于实际候选审核，详见 [本地试修与实际保护复核](overlap-trial-review.md)。以下0.2.35说明保留为原严格策略及历史验证记录。

2026-11-18，0.2.35。此前两张5173旧成功案例的执行能力已接入现有 `remove_text` 默认调用链，不需要任务脚本手工提供每张图的模板框或切换印刷保护模式。

1. DeepSeek仍负责是否去字、文字归属、实例坐标、同组关系及保护内容，原始JSON不改写。
2. 对AI明确标为同组TEXT的多处实例，程序优先从这些已批准区域中验证可靠样本，复用原来的全图字形、局部色差及相邻笔画片段匹配。只定位同款已批准图案，不识读文字或判断店铺。
3. 可靠样本必须具备多个有效字形连通部分并证明存在重复匹配。纯色块不作为文字模板。取不到可靠样本时，保留有界实例区域试修；只有一个旧IMAGE样本框时，不能只擦样本就宣称处理了整图。
4. 对AI明确KEEP的产品/包装印刷、型号文字以及厂家宣传文字，只有几何对应的印刷保护标注可应用用户已批准的有限重建策略。优先保护实际明亮字形；确有水印笔画与印刷相交时，才允许原有PRINT_RESTORE小范围重建。仍限制为精细字形，印刷搜索区实际改动不超过10%，总掩膜不超过25%。
5. 明确厂家Logo、创作者标记、无法绑定到KEEP印刷的结构/未知区域继续精确保留。印刷提取失败不当作“没有保护内容”；大面积损失和宽矩形擦除不能取得印刷重建权限。
6. 生成新候选后，仍执行已有图案残留检查、掩膜外像素检查和DeepSeek实际质量复核；仅候选质量通过后才能进入原保存流程。一次补修仍有问题才转人工，不因初审风险预测而拒绝试修。

派生IMAGE执行标注、原始样本实例ID、实际匹配、保护调整及权限来源记录到 `execution-plan.json` 和修复receipt。它们与原AI回复分开，不把用户执行政策伪装成模型原意。通用单处文字、不同组及大面积/不同角度文字的原处理路径继续保留；重复样式匹配不能保证恢复所有不同形态的水印。

配置仍在 `local/image-options.local.json` 的 `watermark_processing` 内，也支持商品专用配置：

```json
{
  "watermark_processing": {
    "prefer_repeated_glyphs": true,
    "covered_print_policy": "BOUNDED_RESTORE"
  }
}
```

以上为新默认值。`prefer_repeated_glyphs=false` 可停用新的重复图案优先选择；`covered_print_policy=EXACT` 可关闭自动派生印刷重建，保留原始精确保护。`auto_text_masks=false` 也会停用自动重复字形选择。显式既有TEMPLATE_GLYPHS/PRINT_RESTORE协议仍可读取；无修改授权不执行任何去字。

实图回归使用两张SHA绑定原图和2026-11-18冻结的新AI观测，由程序自动推导执行方案。新候选与历史成功候选逐字节一致：机器人掩膜4.98375%，车辆4.99125%；原图/alpha/掩膜外像素保留，已有图案残留检查NO_MATCH。本轮不重新调用语义模型、不读取/修改线上商品；这两例不代表所有图片都能无损修复。正式新Job仍需自己的实际候选质量复核。

证据：本地 `reports/default-precise-watermarks-20261118/`；完整结果以最终验收报告为准。
