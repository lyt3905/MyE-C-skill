# Single-command product workflow

User objective: 程序就能完全自行跑完的一键流程. CLI/runtime only; GUI remains deferred.

Extend the installed `myec-automation` CLI with `process PRODUCT_URL`. After one-time local configuration this command runs the existing V2 chain: validate the URL against the configured backend, identify/verify the current shop, exact-seven preflight, download with pacing/cache/retries, DeepSeek audit, twin-first repair and quality checks, SKU selection, live dry run, restricted save, and a fresh-login independent readback. The program reports CLEAN, partial, review-required, or unknown-write truthfully, with evidence paths and no intermediate user prompts. REVIEW is a valid terminal outcome, not permission to force edits.

Approaches considered: keep generating per-product report scripts (does not meet objective); build another runner (violates reuse requirement); extend existing CLI/runner (selected implementation judgment under user's continuous single-agent instruction). No new semantic auditor, executor, model client or budget ledger.

`process` defaults to configured automatic execution; `--audit-only` never performs preflight/upload/save. It uses `config_root()` and accepts `--config-dir`, `--data-root`, optional `--shop`. Load the key from VLM_API_KEY or local/model-key.local.json only for the operation; never expose it or persist it in a Job. Configurations are resolved independently of cwd. Optional `local/products/<pid>/automation.local.json` and `image-options.local.json` override only that product's policy/rights; site/model/download settings remain at the common config root. Validate URL origin/path before login and infer shop only from authenticated current-shop evidence; configured allowlists still authorize writes. Do not globally enable execution or rights.

The existing execution ledger gains a small Job-location index and current-record read API. The V2 runner can automatically reconcile a known partial prior save from bound evidence, then use the existing restricted claim_followup. Unknown writes and drift remain blocked. No old Job/ledger entry is rewritten as success. A fresh independent reader factory is optional for compatibility, mandatory in the process entry. Use a separate evidence directory so original audit files are not overwritten by readback.

Resume is `process URL --resume JOB_ID`; input URL/shop/mode/config must match that Job. Saved/unknown-write Jobs get readback only, never another save. Completed Jobs return their recorded result. Unfinished audit Jobs reuse the existing checkpoint/cache behavior; no auto-repeat of an entire audit until successful. Each exact-seven preflight and semantic stage keeps its own one-save Job.

Verification: new failing tests for URL/config/key loading, the public command with synthetic network adapters, complete seven-main + audit/repair/twin/SKU/save/independent-reader sequencing, partial followup and unknown-write continuation. All established tests retained. Full offline regression; build/install wheel into isolated environment and run the public command with original Skill/source inaccessible and real network denied. No new real models or production writes for this implementation.

Constraints: single agent; preserve dirty workspace and histories; no add/commit/push; no original Skill edits. New functionality stays in automation/. Existing DeepSeek-only/record-only/description-image/protected-field policies remain authoritative.
