# Excel 通用查询（excel-query）

## 这个技能解决什么问题

对话之间不共享记忆，**能跨对话留下来的只有磁盘文件和技能目录**。
所以「每次都想查这张表」的正确做法是：文件放在固定路径 + 一个技能告诉后来的对话它存在、怎么查。
这个技能就是那一层：`data/` 放文件，`config/sources.json` 记别名，`scripts/xq.py` 负责查。

## 铁律

1. **先摸结构，再查**。第一步永远是 `sources` → `sheets`，不要凭想象猜列名。
   列名不存在时脚本会把真实列名全部列出来——这正是要的结果，别硬试第二次。
2. **绝不要求用户重新上传或再说一遍路径**。表已在 `data/` 或 `sources.json` 里就是常驻的。
3. **回答里带 Excel 行号**。结果里的 `#行` 就是 Excel 里看到的行号，用户说「第 37 行」能直接对上。
4. **表头不在第 1 行时用 `--header N`**，不要为了迁就脚本去改用户的表。
5. 只读。除非用户明确要求写回，否则不要修改原文件（写回请用 `office-xlsx` / `profit-ledger-registration` 等技能）。

## 环境

```powershell
$py = "C:\Users\shana\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\python\python.exe"
$xq = "C:\Users\shana\Documents\GitHub\MyE-C-skill\excel-query\scripts\xq.py"
& $py $xq sources
```
依赖 pandas / openpyxl，已装在上述 runtime 里。`.xls` 需另存为 `.xlsx`。

## 命令速查

| 想干什么 | 命令 |
| --- | --- |
| 有哪些表可查 | `sources` |
| 有哪些 sheet、表头长什么样、表头在第几行 | `sheets --source 别名` |
| 看前几行 | `head --source 别名 [--sheet X] [--header 3] [--rows 10]` |
| 全文找关键词 | `find "关键词" --source 别名 [--column 列名]` |
| 多条件筛选（AND） | `filter --source 别名 --where "店铺~Morph" --where "金额>100"` |
| 分组汇总 | `group --source 别名 --by 店铺 --agg "金额:sum" --agg "订单号:nunique"` |
| 按 Excel 行号看整行 | `row --source 别名 --n 37` |
| 建 SQLite 缓存、看表名 | `tables --source 别名` |
| 任意 SQL | `sql "select ..." --source 别名` 或 `sql --file q.sql` |
| 一个 sheet 里竖排了好几段表 | `blocks --source 别名 [--sheet X]` 看每段的表头行和行范围，再用 `--block N` 查 |
| 报价表算运费 | `quote --source 别名 --to 美国 --weight 350 [--type 普货]` |
| 登记新表 | `add --alias 别名 --path "D:\…\x.xlsx" --copy` |
| 取消登记 | `drop --alias 别名` |

`--source` 省略时，仅在**只有一个表**的情况下自动选中；否则会列出可选项。
`--source` 也可以直接给文件路径。任何命令加 `--json` 输出结构化结果。
输出默认只显示 12 列 × 40 行；宽表（如 300 列的上传模板）用 `--max-cols` / `--column` 收窄。

### 条件运算符（`--where`）

| 写法 | 含义 |
| --- | --- |
| `列=值` / `列!=值` | 等于 / 不等于（数字、文本都行；`列=` 表示空值） |
| `列~值` / `列!~值` | 包含 / 不包含（默认按字面，不区分大小写；加 `--regex` 用正则） |
| `列>数字` `>=` `<` `<=` | 数值比较（整列是数字时），否则按字符串比 |

### 聚合函数

`sum` / `mean` / `min` / `max` / `count` / `nunique`，写法 `--agg "列:sum"`，可重复。

## 典型流程

**用户问「XX 表里那个 62 店 8 月的采购有几笔」**
```
sources                                   # → 找到别名，比如 62店8月-采购登记表
sheets --source 62店8月-采购登记表         # → 看 sheet 名、表头在第几行
filter --source 62店8月-采购登记表 --header 2 --where "店铺~62" --where "月份=8"
```

**列名不确定**
```
head --source 别名 --header 3            # 看真实表头
```

**要算账（加减乘除、跨表 join）**
```
tables --source 别名                      # 得到 SQL 表名和列名
sql "select 店铺, sum(\"金额\") from 表名 group by 1 order by 2 desc"
```
PowerShell 里 SQL 的双引号常被打掉，稳妥做法是写成 `q.sql` 再 `sql --file q.sql`。

## 多段堆叠表（一个 sheet 里竖排了好多张表）

有些工作簿把十几张小表竖着摞在同一个 sheet 里，**每张表各有一套三行表头**
（列名行 → 重量段/分组行 → 单位行），段与段之间隔一两行空行。典型就是 `无忧物流-标准`（17 段）。

这种表**不能**用一个 `--header` 从头查到底，否则第 2 段以后的列名全错位
（曾因此把美国的 0~200g 档误读成 0~150g）。

```powershell
& $py $xq blocks --source 无忧标准            # 列每段：#行范围 / 表头行 / 行数 / 首末国家 / 前 8 个列名
& $py $xq filter --source 无忧标准 --block 4 --where "Code=US"
& $py $xq head   --source 无忧标准 --block 4 --max-cols 30
```

- 段内列名会被拼成可读形式：`普货/201~400g/配送费`、`普货/201~400g/挂号费`、
  `非普货/0~200g/挂号费`、`大包 限重30kg/0-2100g/首重0.5KG`、`大包 限重30kg/2100-30000g/续重/500g`。
- 段与段之间空行不算行，`段N 表头行 ≈ 段N-1 末行 + 2~3`；脚本已自动算好，别手数。
- `--block` 也可以存成别名默认值（`add … --block 4`），之后这个别名就默认查那一段。

### 算运费：`quote`

> **用户的固定约定（2026-11-05 定）**：算运费**一律默认普货**，用户只在是非普货或大包时才会另外说明。
> 所以拿到「国家 + 重量」就直接按普货算，不用反问类型；用户说「带电」「特货」→ 按 `--type 非普货`；
> 用户说「大包」（或重量明显 ≥2kg）→ 按 `--type 大包`。

```powershell
& $py $xq quote --source 无忧标准 --to 美国 --weight 350              # 普货，350 克
& $py $xq quote --source 无忧标准 --to 美国 --weight 150 --type 非普货
& $py $xq quote --source 无忧标准 --to 美国 --weight 1200 --type 大包
```

- `--to` 认中文 / 英文 / 两位 Code（`美国`、`United States`、`US` 都行）；名字正好对上的优先，
  没有正好对上的才退回「包含」匹配（所以查「美国」不会先蹦出「美国本土外小岛屿」）。
- 会自动在全部段里找含这个国家的段、按列名里的重量区间选档，输出 段号 / #行 / 计费档 / 单价 / 合计。
- 小包：`合计 = 重量(kg) × 配送费 + 挂号费`；大包：`首重 0.5kg 价 + 超出部分每 500g 续重价`。
- 计泡类大包（列名带「（计泡）」、只有配送费+挂号费、没有首重/续重）按小包公式算，`计费档` 显示 `大包 0-30000g`。
- 重量超出该段所有档位时不会硬算，会列出这个国家可选的档位。

> 这样后来的对话不用跑 `sheets` 也知道有什么。

## 新增一个表（一次性动作）

```powershell
& $py $xq add --alias "62店采购" --path "C:\Users\shana\Documents\某处\62店8月-采购登记表.xlsx" --copy
& $py $xq sheets --source 62店采购
```
`--copy` 会把文件复制进技能的 `data/`（推荐，原文件挪走也不影响）。
不加 `--copy` 就是原地引用，路径失效时 `sources` 会标 ✗。
直接往 `data/` 丢文件也行，文件名（不含扩展名）自动成为别名。

## 坑

- **表头不在第 1 行**：这类台账常常上两行是标题/说明。`sheets` 会打印前 3 行，据此定 `--header`。
- **合并单元格**：只有左上角有值，其余为空，`sheets` 里能看到；必要时按「同上」理解。
- **多行合并表头**：`--header` 指向带列名的那一行后，被合并的下级列会显示成 `列5`、`列6`…；这时用 `row --n 175` 看整行（按 Excel 行号取值），或 `--json` 拿全量，别硬猜列名。
- **报价表的重量段在表头下一行**：列名行 → 重量段行 → 单位行，所以 `--header` 要指向**列名那一行**，数据从它的 +3 行开始（脚本已处理）。
- **一个 sheet 竖排多张表**：每段表头不同，套一个 `--header` 会让后面的段列名错位（会读出错价格的档位）。先 `blocks`，再 `--block N`；要算运费直接 `quote`。
- **合并单元格被向右填充**：表头里的「大包计费」这类合并标签会被模拟填充，列名仍按真实列宽截断（`blocks` 里显示的「共 N 列」是准的）。
- **金额/日期存成文本**：`--agg :sum` 会自动尝试转数字，转不动的当 0；要精确核对就用 `--json` 看原值。
- **超宽模板**（如速卖通批量上传模板，300+ 列、多行表头）：直接 `find` 关键词比逐列看快得多。
- **大文件**（几万行）：先 `tables` 建 SQLite，再 `sql` 查，比反复读 xlsx 快一个数量级。
- **同名多表**：`--source` 支持子串匹配，但匹配到多个会报错要求写全名。
- 结果默认只显示 40 行（`--limit` 调整），要全量就 `--json`。
