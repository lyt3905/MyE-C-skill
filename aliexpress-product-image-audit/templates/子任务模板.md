# 子任务模板：单件商品审核（token-opt-v1）

> 流程版本：`token-opt-v1`。Lead 拒收缺少该版本号与 `run_metrics.json` 的结果。
> 用法：把「任务正文」发给一个 subagent，替换 `{{PID}} / {{TITLE}} / {{SHOP_ID}} / {{PREFIX}} / {{EXPECTED_STATUS}}`。一件商品一个子任务。
> 正本在项目目录；skill 副本为 `templates/子任务模板.md`。改完跑 `python check_template_sync.py --push`。

## 任务正文

只审核并整改 **{{PID}}（{{TITLE}}）**。默认模式是完成严格计划与 dry-run 后写回该商品；只有用户明确说“只读/不写站”时才停在 dry-run。只允许写该商品与 `work/pp_{{PID}}/`；不碰其他商品、共享脚本、数据库，不发布。

环境：
- cwd：`C:\Users\shana\Documents\deepseek-harness\default-workspace\ae-img-audit`
- Python：`.\.venv\Scripts\python.exe -X utf8`
- 站点：`https://39.107.244.239`；当前店铺先切 `shopId={{SHOP_ID}}`
- 标题前缀：`{{PREFIX}}`；终态保持 `{{EXPECTED_STATUS}}`

### 1. 先跑紧凑预审

```powershell
.\.venv\Scripts\python.exe -X utf8 audit_one.py {{PID}} --shop {{SHOP_ID}}
```

随后创建严格计划骨架（自动复用 `audit_product.json`，通常不联网）：

```powershell
.\.venv\Scripts\python.exe -X utf8 apply_token_plan.py init {{PID}} --shop {{SHOP_ID}}
```

先只读 `work/pp_{{PID}}/audit_context.md`。只有其中列出问题时才读 `audit_flags.json` 对应段；不要把 `audit_raw.json` 全文贴入上下文。`run_metrics.json` 只在结束时读摘要。

按 context/flags 加载资料：
- 图片异常/需要改图：`SOP-商品图片整改.md`
- 标题、编号或品牌异常：`SOP-商品标题重写.md`
- 写回前：`站点接口备忘.md`
- 水印/边框/OCR误报/低清/编号争议：`判例与陷阱.md`

`mode=fast` 仍要看脚本生成的拼版/异常证据；`mode=deep` 只深审 flags 指向的图片和字段。

Token 预算硬规则：
- 先看全池低分辨率拼版，只对 flags 指向或目视不确定处打开原图；原图查看目标≤12次。
- 同一证据不重复读；不得把原始 OCR、完整产品 JSON、长终端日志贴入上下文。
- 禁止创建 `s1.py→s15.py` 式一次性脚本；默认只编辑 `plan.v1.json`，异常修图最多 1 个商品内脚本。
- 模型请求目标≤45；无法从 Python 得到的请求/token 数必须保持 `null`，由会话账本补，不得猜数。

### 2. 必须检查的四维

- 图片：全池；main≤6；main/detail/sku短边≥800；盒照保留；描述与SKU引用同步；擦裁后 OCR+残差复检。
- 标题：`titleEn` 前缀=`{{PREFIX}}`、≤120；原始 `title` 不动；改后 translate-title，最多2次。
- 编号：有可靠来源则填；官方带横线优先；标题双格式；无来源不编造。
- 品牌：变形玩具/变形金刚→Hasbro `200017853`；否则→Bandai `200014695`。`logoCode` 不动。

### 3. 严格计划与写回硬规则

- 只编辑 `work/pp_{{PID}}/plan.v1.json`（schema=`token-opt-plan/v1`）；旧 `plan.json` 只作历史证据，禁止交给旧 `pipeline.apply_plan()`。
- 图片池写最终有序数组；本地成品放商品目录并写 SHA256；描述只允许完整 URL 精确替换/删除，禁止按文件名模糊替换。
- 先离线校验，再 dry-run：

```powershell
.\.venv\Scripts\python.exe -X utf8 apply_token_plan.py validate work/pp_{{PID}}/plan.v1.json
.\.venv\Scripts\python.exe -X utf8 apply_token_plan.py run work/pp_{{PID}}/plan.v1.json
```

- dry-run 必须是零上传、零 `Site.save()`。默认写站模式下，Lead 给该 PID 派发“审核”任务即包含真实写回批准：dry-run 通过且确有改动时，把 `approval.site_write` 改为 true，并使用 `--apply --confirm-pid {{PID}}`，不再等待第二次用户确认。用户明确要求“只读/不写站”时，`approval.site_write` 必须保持 false，并停在 dry-run。
- 若计划无实际改动，不得为了触发 save 伪造字段变化，直接报告无需写回。
- 执行器只允许一次 `Site.save()`；禁止裸 PUT，写前完整状态哈希防漂移，写后立即回读。
- 每次 save 显式带完整 `identityJson` JSON字符串与当前 `weight`；`logoCode`、原始 `title`、price/status/SKU非图片字段不得漂移。
- `titleTranslationZh` 只用 `/translate-title`；`shippingFee` 不写。
- 不调用 `Site.status()`、不生成AI封面、不发布；状态必须保持 `{{EXPECTED_STATUS}}`。

### 4. 紧凑计划与报告

`plan.v1.json`：
- `review.keep_summary` 只按池汇总，例如 `{"main":5,"detail":12,"sku":2}`。
- `review.actions` 只列 CROP/ERASE/DELETE/REPLACE/WEB_DEFER 等异常，含理由、证据与回滚 URL。
- 真正写入内容只放 `desired`；不允许任意 `extra`、整份 SKU 覆盖或 `shippingFee/status`。

报告用固定渲染器生成，必要时只补“不确定/遗留”事实，不手写长篇：

```powershell
.\.venv\Scripts\python.exe -X utf8 render_token_report.py {{PID}}
```

交付：
- `报告_{{PID}}.md`：25–40行，依次写结论、实际改动、标题/编号/品牌、线上复检、遗留、回滚；必须有 `流程版本：token-opt-v1`。
- `ba.jpg`：只覆盖被处理图与关键结构变化。
- `audit_flags.json`、`run_metrics.json`、`plan.v1.json`、`compiled_plan.json`、`product_before.json`；真实写回后另有 `product_after.json`、`apply_receipt.json`、`live_check.json`。
- 给 Lead 的消息≤10行，不粘OCR原始日志；必须写 `流程版本：token-opt-v1 / 预算状态：PASS|WARN|UNKNOWN`。未从会话账本补齐时只能写 UNKNOWN，不得假报 PASS。

### 5. 完成前自查

```powershell
.\.venv\Scripts\python.exe -X utf8 audit_one.py {{PID}} --shop {{SHOP_ID}} --force
```

必须满足：状态未漂；main≤6；短边≥800；描述无死链；无未裁定店招/水印；标题前缀与长度正确；回译非空；modelCode与标题格式正确；brand符合规则；logoCode/weight未漂。

## Lead 独立验收

1. 先拒收缺少 `workflow_version=token-opt-v1`、`run_metrics.json` 或严格 `plan.v1.json` 的结果。
2. 不采用子任务自述，重新运行 `audit_one.py {{PID}} --shop {{SHOP_ID}} --force`；`--force` 重下图片，但相同内容仍复用 OCR 证据缓存。
3. 只读紧凑 `audit_flags.json`、异常证据、`ba.jpg` 与报告；必要时再打开 `audit_raw.json` 的具体图片条目。
4. 核对写前/写后 status、brand、weight、logoCode、price、图池数量与标题字段；确认收据仅一次 Site.save、零 status 调用。
5. 有错误则明确返工点；通过后把版本、预算和紧凑验收写 `work/pp_{{PID}}/lead_verify.json`。
