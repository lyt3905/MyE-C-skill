# 逐图片结果与耗时

标准Workflow完成后，同一Job自动生成 `image_observations.json`，并在report_data.json/report.md中提供入口。数据只覆盖main/detail/sku；不读取audit_product里的固定Description。该文件仅记录观察，不授权写入，也不生成Ground Truth。

每张图片包含审核ID、三类业务类型、审核索引、原数据定位、URL、源SHA、下载错误；OCR文字及疑点、边缘/重复图信号、残差、高通、模板匹配位置、ROI坐标和文件SHA；审核队列融合判断与逐模型事件；本地阶段耗时和执行/缓存状态。

模型事件区分实际调用、缓存、错误、预算阻断。记录provider/model、item_id、attempt、耗时、有效结果及Token状态：ACTUAL_REPORTED / ACTUAL_ZERO / UNKNOWN / NOT_CALLED / BUDGET_BLOCKED。无效JSON仍记录服务端已报告消耗；负数usage不进入有效汇总。缓存命中不伪造一次ACTUAL_ZERO模型调用。没有事件采集的历史Job不倒推供应商、逐图Token或耗时，保持UNKNOWN/null。

这些逐图事件只覆盖机器审核队列；独立候选质量模型调用在quality_metrics.json中单独保留。因此逐图Token相加不能替代整个Job的总消耗。download耗时按唯一URL实际读取计量，同URL多处出现会重复显示同一耗时，不能重复相加。CV总耗时包含原审计的残差统计；residual字段是之后残差证据图生成的独立步骤。模型attempt耗时包括准入、等待与验证，不是纯服务端推理时间。OCR的CACHE_RECLASSIFIED表示重新处理缓存文字，不表示重新OCR推理。

## 恢复后的记录完整性核对

全Job汇总现在将持久预算中的admitted_requests与主审核、独立质量阶段的reported_requests进行核对。不一致时metrics_completeness=INCOMPLETE、actual_tokens=null、token_status=UNKNOWN，并添加MODEL_METRICS_INCOMPLETE；不会把恢复后缓存命中0次请求误当此前零消耗，也不会把预算预留Token当实际消耗。

VERIFIED只表示上述请求计数相等，不证明逐图历史完整、供应商usage可靠、审核结论正确或允许生产执行。缓存事件仍是NOT_CALLED；历史某阶段usage未知时，即使计数相等，汇总仍UNKNOWN。逐图事件覆盖实际保存的主审核事件，不能倒推出中断时丢失的调用。
