# 商品图片审核：判例与陷阱（按需读取）

> 本文件承接旧版 `SKILL.md` 的历史判例、擦除配方和易错机制。常规单件审核不要默认加载；只有 `audit_flags.json` 出现水印、边框、残差、低清、重复、编号争议或接口异常时，才按关键词读取相关段落。

## 1. 先判真伪，再动图片

### 必须处理

- 站外站标或别家店招：`78动漫`、`DP ROBOT Store`、`Orange Toy Store`、`SayHi Toys`、橙子切片 + `TOY`、心作玩具店章。
- 第三方促销或导流：`In stock`、`Delivery within 72 hours`、店铺欢迎页、网址、二维码、中文政策页、中文参数条。
- 主图中的中文促销海报、装饰边框、自制拼版；详情拼版里的 `In stock` 可按用户口径保留。

### 默认保留

- 厂牌/品牌 VI：`UNIQUETOYS`、`MS-TOYS`、`GALAXY TOYS`、`ASTOYS`、`VELOCITRON`、`TMT`、`BINGOTOYS`。
- 官方署名与说明：`@TMT模玩社`、`@DNA_Design`、`SHOT BY …`、`© … STUDIO`、`UPGRADE KITS`、`ORIGINAL`、日文试作品说明。
- 商品包装自身印刷：品牌、型号、年龄标、警告语、Takara Tomy 厂标；盒面翻折造成的倒印不是重复水印。
- AI 封面的 `PureSun Toys` 自家品牌条；是否保留其中 `In Stock` 由 Lead 的批次口径决定。

### 常见 OCR 误读

- `SOO COLLECTION` 往往是 `SPEEDIA 500 COLLECTION`。
- `LINGOTOYS` / `VINGOTOYS` 可能是斜切字母 B 的 `BINGOTOYS`。
- `OEngrenni` 可能是极淡 `@英格伦lingrainn`；需要放大和残差确认。
- 单个 `京`、`小肉` 等低置信命中常是纹理或零件轮廓。

判定至少取两类证据：2–4× 目视、同池干净版、SKU/盒面、官方渠道、残差图。OCR 字串本身不是结论。

## 2. 擦除与裁切配方

| 形态 | 优先方法 | 质量门禁 |
|---|---|---|
| 整宽贴底横幅 | 纯裁切，再补方 | 不得切主体；裁后短边仍合规 |
| 纯白底角落店标 | ROI 纯白填充，保存 PNG | ROI 外逐像素差为 0 |
| 虚化背景小角标 | 小 ROI TELEA inpaint | 主体零改动、无灰糊 |
| 中灰半透明横条 | ROI 3×，mask 外扩，TELEA + 羽化 | 2× OCR + 人眼复检 |
| 平铺同字形站标 | 字形 alpha 模板；背景与主体分层处理 | 不能破坏零件纹理 |
| 白底极淡 1–2px 字 | 环形邻域中值/局部插值 | 4× 灰度拉伸无残字 |
| 纯平背景整幅淡字层 | 逐列或逐行中值插值 | ROI 外 diff=0 |
| 横贯主体的大水印 | 换源；仍不可用则删图 | 宁缺勿滥，禁止涂抹交付 |

不要一上来整图 inpaint。整图重采样会造成 ROI 外变化；大核中值会产生明显涂抹；LaMa 可能按上下文把文字重画回来。

## 3. 三道扫描门禁

常规预审由 `audit_one.py` 负责收敛输出，但视觉质量仍用三道证据：

1. 全图 OCR；
2. 顶部/底部约 28% 放大 OCR；
3. `medianBlur(61)` 残差或 4× 灰度拉伸。

1× OCR 会漏中文与极淡水印。VLM 只能初筛：无图模型时可用双 VLM + OCR + 残差替代初筛，但 Lead 最终要看异常图或对比图。

## 4. 图片结构判例

- 主图不超过 6 张，优先删除：装饰/拼版 → 他店水印 → 中文促销 → 重复正面 → 信息量最低角度。
- 官方棚拍、盒照不因“文字多”删除；盒照是包装 SKU 的关键证据。
- 低清图不允许通过上采样“凑 800”；有干净替代就换，没有就少一张。
- 主图不足的补图顺序：详情池新角度 → 同店已审同款旧商品（Lead 目视确认）→ 接受少图。不要硬凑重复图。
- SKU `no retail box` 不能挂盒照；`with retail box` 优先挂盒照。若只有同一张合照能同时表达多角色或多款规格，可共用，但报告写清原因。
- 改图 URL 必须同步 `descriptionJson`；删前还要查 SKU、详情和描述引用。
- OSS 常以 `.jpg` 扩展名装 WEBP；用 `cv2.imdecode`，上传前转 PNG/JPEG。

## 5. 标题、编号和品牌判例

- 标题前缀按店铺：shana1=`Hot Sale`，62店=`In Stock`；`titleEn` ≤120。
- 编号有则填，优先官方带横线写法；标题双格式：`NA-H74 NAH74`。字数不足先删修饰词，最后才删扁平版本。
- 官方本来不带横线的写法保持：Hasbro `F5759`、`LS03F`、`44BB` 等。
- 盒背常见 `F5xxx / F3xxx Asst.`：前者是单品货号，`Asst.` 是整箱号；`Legacy`、`SPEEDIA500`、`SS86` 通常是系列名，不直接当 modelCode。
- 无牌升级件不借用被升级主体编号；找不到可靠编号就留空，不编造。
- 脏值如 `9`、`84-86`、多编号粘连要先核本体，再清空或改正。
- 品牌字段按用户最新规则审核：标题/商品属于变形玩具或变形金刚 → Hasbro `200017853`；否则 → Bandai `200014695`。`identityJson.logoCode` 保持原值。
- `translate-title` 是 LLM 直译，角色名可能反复错误；默认最多尝试 2 次，仍不稳定就保留可接受结果并登记，不无限重试。

## 6. 写回与状态陷阱

- 内容写回只用 `Site.save()`；禁止裸 PUT。
- 每次 save 必须带完整 `identityJson` JSON 字符串和当前 `weight`。即使显式传了 identityJson，个别请求回读仍可能丢 modelCode；必须立即回读，丢失就单独再 save 一次恢复。
- `titleTranslationZh` 只能调用 `/translate-title` 生成；save 里写无效。
- `shippingFee` 是 weight 派生值，永不手写。
- `Site.status()` 会推进流程并可能生成 AI 封面；没有 Lead 明确要求就不调用。
- 当前店铺是服务端会话上下文。商品 404 或列表不对时，先 `PUT /api/admin/shops/current {"shopId":7}` 再重读。
- AI 封面流程可能重传图片并换 UUID；验收按画面/pHash，不按旧 URL 精确匹配。
- 用户 UI 操作可能清空 `titleTranslationZh`；重新调用 translate-title 即可。
- 页脚模板图和带第三方域名的整店页脚不要单件擅删，登记给 Lead 统一裁定。用户 2026-11-11 裁定：全店页脚模板图（如带 `wallpapers-den.com` 第三方小水印）**「不管」**，维持现状，只登记不处理。

## 7. 执行与验收陷阱

- 一件商品一个子任务；模型/上游切换可能杀掉所有在跑子任务，但 `work/pp_<pid>/` 或 `work/r2_<pid>/` 产物通常仍在，重派应从断点续跑。
- 图片写回后 UUID 会变；写完重新 `s.product()`，不要缓存写前 URL。
- 报告只逐条列异常和实际改动；KEEP 按池汇总，不逐图写几十行。
- Lead 不读取数千行 OCR 原始日志；默认只看 `audit_flags.json`、`lead_verify.json`、异常证据图和 `ba.jpg`。
- `audit_flags.json` 的 `mode=fast` 只表示自动扫描没发现高风险，不替代对拼版/异常缩略图的人眼确认；`mode=deep` 才加载对应 SOP 与本判例库。
