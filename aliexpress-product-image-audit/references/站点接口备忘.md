# 站点接口备忘（https://39.107.244.239 管理后台）

来源：线上前端 bundle `/assets/index-DphTRj4S.js`（2.81 MB，2026-11-07 抓取）+ 实测验证。

## 1. 状态机与中文标签

前端状态表（原样）：

```
{PENDING:"待编辑", EDITING:"待生图", READY_TO_PUBLISH:"待发布", DONE:"已定稿"}
推进链 {PENDING:"EDITING", EDITING:"READY_TO_PUBLISH", READY_TO_PUBLISH:"DONE"}
```

**关键：`EDITING` 就是界面上看到的「待生图」**，不是「编辑中」。所以商品一进 EDITING，看着就像"被推进到待生图了"。

推进按钮走 `POST /api/admin/products/{id}/status`，body 是整个商品对象（里面 `status` 字段=目标状态）。
商品有在跑的任务时返回 **409**「商品存在正在执行的任务，请等待任务完成后再推进」。

## 2. 「保存」按钮打的是哪个接口

前端代码：

```js
kt.put(`/admin/products/${id}`, xi(), { params: sxt(mode) })
// sxt(mode) = mode === "navigation" ? undefined : { autoSave: true }
```

即 **`PUT /api/admin/products/{id}?autoSave=true`**，body 由表单字段 + 图片集合 + 描述集合组成（titleEn / descriptionJson / images / skus / price / brand / identityJson / status）。

**body 里到底送了什么**（前端 `Ybt()` 组包，2026-11-07 从 bundle 读出 + 4826 实测印证）：

```js
const {identity: o, ...i} = formValues;
return {...i, identityJson: qbt(o), images: ..., skus: ..., descriptionJson: JSON.stringify(desc)}
// qbt(): {logoCode: logoCode.trim() ?? ""} ；modelCode 只在非空时才写进 JSON；最后 JSON.stringify
```

两条必须记住的推论：
- `identityJson` 是**字符串**不是对象：`s.save(extra={'identityJson': json.dumps({...})})`；传 dict → `HTTP 400`（报错体为空）。
- **`titleTranslationZh` 不在 body 里**（它是 `useState` 单独存的，不在表单字段中）→ 用 `save()` 写它永远无效，要用 §4 的 `translate-title` 接口。
- **这个 PUT 是「缺字段填默认值」的全量覆盖，不是部分更新**（2026-11-07 四次实验定案）：body 里没有 `weight` 就把重量重置为**后端缺省 0.3**，并立刻按新重量重算 `skus[].shippingFee`（0.2→0.3 时 7.43→8.8）。**0.3 是后端字段缺省，不是采集端/店铺的默认 0.4**：实测 `0.2→0.3`、`0.4→0.3`，无论商品原值多少都被拉平到 0.3，与商品、类目、店铺配置都无关（`/api/admin/shops` 里没有重量配置）。`brand` 缺失时**不会**被重置。
- ⚠️ **2026-11-09 更正：`identityJson` 也会被重置。** body 里不带 `identityJson` 时，服务端把它写成 `{"logoCode":""}`，**`modelCode` 键直接丢失**（4875/4876/4878/4880/4881/4882/4884/4886/4887 九件实测复现，2026-11-07 在 4826 上得出的「不会被重置」结论只在那件空编号商品上成立——空 `identityJson` 本来就是 `{"logoCode":""}`，看不出差别）。
  → **规则：每一次 `Site.save()`（哪怕只换一张图、只改标题）都必须显式带 `extra={'identityJson': json.dumps({...})}`，写完 `s.product(pid)` 回读核对。**
  - 应对：`site_client.py` 的 `Site.save()` 已把商品当前 `weight` 一起回传；要改重量显式 `extra={'weight': x}`。
  - `shippingFee` 是 `weight` 的**只读派生值**（前端输入框 `disabled/readOnly`，由 `POST /admin/products/calculate-sku-amounts {price, weight, discount, pricingCurrency}` 生成）——**永远不要自己写**，改重量即可。
  - 实测换算（同重量两种费率＝币种/运费模板差异）：0.01→4.75/4.82、0.02→4.96、0.03→5.03、0.08→5.78、0.1→6.06、0.2→**7.43**、0.3→**8.8**、0.4→10.02/10.17、0.5→11.37/11.54、0.6→12.72/12.91、0.7→14.07/14.28、0.8→15.42/15.65、0.9→17.02、1.0→18.12/18.39、1.5→24.88/25.25、1.8→29.36、2.0→32.1。

保存按钮之外，页面还有自动保存（autosave），也是同一个接口带 `autoSave=true`。
AI 合图任务运行中前端会拦住保存并提示「AI 合图处理中，当前修改将在任务结束后自动保存」。

## 3. 实测对比（pid 4571，2026-11-07）

| 调用 | 图片 | 状态 | AI 封面 |
|---|---|---|---|
| `PUT /api/admin/products/{id}?autoSave=true` + main[0] 换新上传图 | 只有 main[0] 变成新 id（ab774d36），其余图 id **不变** | 仍 PENDING | 不插入 |
| 同上，body 里不带 status 字段 | 正常保存 | 仍 PENDING | 不插入 |
| `PUT /api/admin/products/{id}`（**不带** autoSave） | 全部图片改名重传 | 跳 EDITING 或 READY_TO_PUBLISH | 自动生成并插到 main[0] |

结论：**`autoSave=true` 是「只存内容、不动流水线」的那个开关**。不带它就走 INGEST_POST_PROCESS 全流程。

## 4. 其它可用接口

| 接口 | 用途 |
|---|---|
| `POST /api/admin/uploads/images`（multipart，字段名 file） | 上传单图，返回 `{url}` |
| `POST /api/admin/products/{id}/images/blacklist` `{imageUrl}` | **删除该图并加入黑名单**，后续采集同 URL 图片自动过滤（对"整店图都带别家水印"的采集源很有用） |
| `POST /api/admin/products/{id}/replace-image-links` | 批量替换商品内图片链接，返回 replacedCount / failedCount / skippedCount |
| `POST /api/admin/products/{id}/main-images/covers`（multipart files） | 主图合成工作台保存合成图 |
| `POST /api/admin/products/{id}/main-image-upload-sessions` + `GET /api/admin/main-image-upload-sessions/{sid}/events` | 主图上传会话 / SSE 进度 |
| `GET /api/admin/products/{id}/active-tasks` | 在跑任务列表 |
| `POST /api/admin/products/{id}/image-cutouts` `{imageUrl}` | 单图抠图，返回新 url/width/height |
| `POST|GET /api/admin/products/{id}/ai-cover-generation`、`/restart`、SSE `/events` | AI 合图（封面）任务 |
| `POST /api/admin/products/{id}/title-generation`、`/restart`、`/translate-title`、SSE `/events` | 标题生成 / 直译。**`/translate-title` 传 `{"titleEn": "..."}`，返回并落库 `titleTranslationZh`**（4826 实测：调前 `None`，调后得中文，`titleEn` 不变） |
| `POST /api/admin/products/{id}/description-images/translate` `{imageUrl}`；`/translate-crop`（multipart originalImageUrl+crop） | 详情图翻译 / 翻译前裁剪 |
| `POST /api/admin/products/{id}/aliexpress/preflight`、`/publish`；`GET /aliexpress/status` | 速卖通发布前检查 / 发布（我们只读不点） |
| `DELETE /api/admin/products/{id}` | 删商品 |

## 5. 因此对工具链的改动

`Site` 类**现在位于 `scripts/site_client.py`**（`pipeline.py` 反向 import 它，单一实现），用 `.venv/Scripts/python.exe` 下测通：

```python
s.save(pid, images={'main': [...]}, desc=None, extra=None)   # 等价于「保存」按钮，autoSave=true
s.blacklist(pid, image_url)                                   # 删图 + 拉黑
s.replace_links(pid)                                          # 批量替换图片链接
s.status(pid, 'EDITING'|'READY_TO_PUBLISH'|'DONE')            # 推进按钮（原样保留）
```

**新规范：图片整改一律用 `s.save()` 写回；要推进状态时单独调 `s.status()`，两件事分开做。**

### 凭据放在哪（2026-11-07 起）

`site_client.py` 里**不写账号密码**，按下列顺序找（先找到先用）：

1. 环境变量 `AE_SITE_BASE` / `AE_SITE_USER` / `AE_SITE_PWD`
2. 环境变量 `AE_SITE_CFG` 指向的 json
3. 当前工作目录的 `cfg.local.json`（现行做法：`ae-img-audit/cfg.local.json`）
4. 从当前目录往上最多 3 层找 `cfg.local.json`
5. `~/.dsh/secrets/ae-site.json`

`cfg.local.json` 格式：`{"base": "https://39.107.244.239", "user": "...", "pwd": "..."}`。
找不到就抛 `RuntimeError: 缺少站点凭据`（**不会**回退到任何硬编码密码）；`CFG["_from"]` 告诉你它读了哪个文件。
`cfg.local.json` 已在 `.gitignore` 里，永不入库。
