# 速卖通商品换主图（全屏截图 + 真实鼠标）

## 零、统一口径（与 `publish-aliexpress-product` 完全一致）

**一套眼睛，一套手，一个坐标空间。**

| 环节 | 唯一做法 |
| --- | --- |
| 眼睛 | `cua_driver_native__get_desktop_state {screenshot_out_file}` → 全屏 PNG，**1920×1080** |
| 手·鼠标 | `click {scope:"desktop", x, y}` → SendInput，`route:"global_input"`，真实光标真的动 |
| 手·键盘 | `type_text` / `press_key` / `hotkey`（`scope:"desktop"`，打到当前前台） |
| 长文本 | `clipboard_write` + `hotkey {scope:"desktop", keys:["ctrl","v"]}` |
| 滚轮 | `scroll {scope:"desktop", x, y, direction, amount}` |
| 拖拽 | `drag {scope:"desktop", from_x, from_y, to_x, to_y, duration_ms, steps}` |
| 认窗口/认店 | `list_apps` / `list_windows` / `get_window_state`（只读） |

**禁用**：`browser_*`、CDP/DevTools、`set_value`、`background` 模式的任何投递、
`click {scope:"window"}`（坐标在压缩过的窗口图里，易点错）。

**坐标纪律（旧口径已作废）**：

- ❌ 不再有「截图坐标 − 窗口左上角 (−15,−15)」这回事 —— 全屏坐标系天然对齐；
- ❌ 不再有「视图坐标 × 2.4」 —— `get_desktop_state` 的 PNG 像素 == 点击像素；
- ❌ 不再用「窗口矩形截图 + 窗口偏移」这套老办法（`screen.py` 的物理坐标体系，见第十二节）。

> 一句话：**看到哪就点哪，图上量出的数直接填进 `x, y`。**

## 一、这个技能解决什么

商品主图要做成「白底 + 卖点角标 + 店铺 logo 条」的 800×800 合成图时，速卖通官方路径是安装
**AliExpress 图片编辑器** 扩展，在扩展里抠图/排版，再「回填到商品页」。

难点：扩展页是 `extension://gdjpcbniflfigkmbjhclbbcjdplhmheb/editor/index.html` 协议，回填弹层是原生浮层，
**DOM 选择器点不到，调试端口也开不了**（Edge 136+ 对默认 Default 配置禁用 `--remote-debugging-port`）。

所以只能：**截屏当眼睛，真实鼠标键盘当手。**

> 前提：卖家账号是真人已登录状态。脚本绝不代填账号密码。

## 二、适用 / 不适用

| 适用 | 不适用 |
|---|---|
| 已登录卖家后台，要把某商品换成合成主图 | 没登录 / 需要过滑块验证 → 停手交人 |
| 逐张核对发布页字段（标题、类目、海关属性） | 需要批量抓取商品数据的场景（那该用接口） |
| 扩展已装、图标在地址栏右侧 | 扩展被卸载 → 先在 Edge 扩展页装回来 |

**不解决的问题**：风控（指纹/节奏/账号行为）。遇滑块、验证码、异常登录提示 → 立即停止，交给人工。

## 三、前置检查（每次开工先跑）

```
cua_driver_native__check_permissions          # 要 uia:true
cua_driver_native__list_apps                  # 找 msedge.exe 的 pid
cua_driver_native__list_windows { pid }       # 看标题里的 Edge 配置名（'个人' / '个人 2'）
cua_driver_native__get_desktop_state { screenshot_out_file: "...\\ie-pre.png" }
```

- 屏幕：**每次开工都要实测**——同一台机器会在 **3840×2160@200%**（本机外接屏 XMI27B4）与 **2560×1440@150%**
  （接游戏串流虚拟显示器 / 本机屏 TMA2031）之间跳变；`cua_driver_native__get_screen_size` 报的是物理像素，
  非 DPI-aware 的自建脚本里 `GetSystemMetrics` 还会被虚拟化成 1707×960。**分辨率一变，旧坐标全部作废。**
- **开着的 Edge 窗口常有多个（不同 Edge 配置）**：`channelId` 才是店的硬标识，别按 pid 认定

| 窗口标题里的配置名 | channelId | 店铺 |
| --- | --- | --- |
| `… - 个人 - Microsoft Edge` | **2465459** | PureSun Toys Store |
| `… - 个人 2 - Microsoft Edge` | **2348249** | 另一个店（10.1 那批 6 个商品都在这里） |

开工第一步先说清"这次动哪个店"，并让目标窗口在最前面（真实点击一下页面即可，不要程序化抢前台）。

## 四、坐标怎么来（不要凭感觉）

1. `get_desktop_state` 截一张全屏图 → 用 read 工具看图（别让 base64 进上下文）；
2. 目标小/密集就裁图放大 2 倍再看：
   ```python
   from PIL import Image
   im = Image.open(r"...\.cua-shots\ie-1.png").convert("RGB")
   im.crop((x0, y0, x1, y1)).resize(((x1-x0)*2, (y1-y0)*2), Image.LANCZOS).save(r"...\crop.png")
   ```
3. **能按颜色量就别靠眼睛**（黄色角标、橙色告警、蓝色按钮都很容易聚出来）：
   ```python
   px = im.load()
   pts = [(x, y) for y in range(y0, y1) for x in range(x0, x1)
          if (lambda r, g, b: r > 200 and 55 < g < 145 and b < 95)(*px[x, y])]
   ```
4. 落点取目标**几何中心**，不要贴边；按钮有内边距，宁可往里 5–10 px；
5. 点完**立刻再截一张图核对**，别连着点第二下。

## 五、完整流程

> 每一步都是六拍：**截图 → 看图 → （必要的话）告诉用户 → 动作 → 再截图 → 断言**。

### 步骤 0：进入商品发布页

发布页 URL 形如
`https://csp.aliexpress.com/ait/cn_pop/item_product/product_publish?productId=<PID>&channelId=<CID>`

在新标签页打开（**绝不在已有发布页里跳转**，原因见第六节）：

```
hotkey  { scope:"desktop", keys:["ctrl","t"] }              # 新标签
click   { scope:"desktop", x: 960, y: 47 }                   # 点地址栏（坐标现量）
hotkey  { scope:"desktop", keys:["ctrl","a"] }
clipboard_write { text: "<发布页URL>" }
hotkey  { scope:"desktop", keys:["ctrl","v"] }
press_key { scope:"desktop", key:"return" }
```

核对：面包屑「商品管理 › 商品发布」、右上店铺名、右栏「N 项待优化」。

### 步骤 1：点开图片编辑器扩展

扩展图标在**地址栏右侧**，橙色圆角方块（白底图片图标）。悬停可看名字确认是「AliExpress 图片编辑器」。

```
click { scope:"desktop", x: <图标中心>, y: <图标中心> }
```

- 位置随窗口宽度变化，**务必先截图量一次**（旧物理坐标 ≈ (2725, 50)，新口径按 ÷2 起步 ≈ (1362, 25)，必须实测）
- 打开后是新标签页：`extension://…/editor/index.html?session=…`

### 步骤 2：等抠图跑完

编辑器会自动对原始素材抠图（一般 6 张，十几秒～1 分钟）。

**判断标准**：画布上方进度变成 **`6/6 成功 0 失败 0 进行中`**，且「生成主题」按钮由灰变蓝。
没到就别急着往下 —— 排版没完就点回填只会空跑。隔几秒截一张图轮询，别死等固定秒数。

### 步骤 3：生成 + 回填

```
click { scope:"desktop", x: <生成主题>, y: <生成主题> }      # 可选，打开时通常已自动生成一次
# 复核画布效果后回填（顶栏最右）：
click { scope:"desktop", x: <回填到商品页>, y: <回填到商品页> }
```

回填后**必须截图看缩略图行**，三种行为都出现过：

| 情况 | 现象 | 怎么办 |
| --- | --- | --- |
| A | 弹「已添加图片」，关掉弹窗后缩略图**末位已有**合成图 | 走步骤 4 判断要不要拖 |
| B | 弹弹窗，但缩略图行**没有**新图 | 点蓝色「确认上传」→ 新图出现在末位 → 走步骤 4 拖拽 |
| C | **根本不弹窗**，图片已替换主图或落到末位 | 靠截图判定，别假设 |

铁律（都是踩出来的）：

- **弹窗开着时绝对不要按 ESC** —— 会把「已添加图片」的上传中断，图库里根本没有合成图（Swoop、MX-45Y 各踩一次）；
- 蓝色「确认上传」**先看再点**：缩略图行末位还没有合成图时必须点（2026-10-31 实测 #13：点了才出现第 6 格）；
  末位已经有一张同样的合成图时才点 = 多插一张重复图（2026-10-27 商品 6）；灰色按钮永远不点；
- **回填/确认上传之后，绝不 `ctrl+r` 重载，也绝不切走再切回来** —— 新图只在页面内存里，重载即丢。
  这是 2026-10-30 整批 29 项"白做"的根因，详见「十一之三」；
- 弹窗是否出现靠**遮罩亮度**判定：截一块区域算灰度均值（旧值 <190 即弹窗出现），别靠窗口标题；
- 出现两条红色 `FAIL_SYS_ILLEGAL_ACCESS: 非法请求` **属正常**（首次取上传地址失败后自动重试）；
- 弹窗一旦被切标签/刷新弄丢就看不到进度了。

### 步骤 4：把合成图拖成主图（**先确认需不需要拖**）

先看「商品图片」那一行：第 1 格（`* 主图`）已经是带角标的合成图 → **跳过本步**。

需要时：

```
drag { scope:"desktop", from_x: <末位缩略图中心>, from_y: …, to_x: <主图槽位中心>, to_y: …,
       duration_ms: 500, steps: 20 }
```

- **拖拽的语义是「交换位置」，不是插入**：末位拖到第 1 格 → 它变主图，原第 1 格退到第 2 格，**总数不变**。
  所以"有一张重复合成图、只想让新那张当主图"时，直接把末位拖到首位即可，**不用删除**。
- 成功标志：`* 主图` 下方那张变成合成图（蓝框），原图退到「更多图片」第 1 位。
- 缩略图横向间距约 117 px（新口径，旧物理 233 px），主图槽位中心按截图现量。
- 拖完一定要截图确认顺序真的变了；没变就重拖，落点取目标缩略图正中。

> ⛔ **不要"重新加载商品 URL 让它自动进主图位"** —— 这曾是一条错误经验（10-27 观察到 4 个商品重开后是 ALREADY_MAIN）。
> 真相是：那些商品的主图早在**上一批**就已经被服务端存成合成图了，重载只是把**本次**回填的新图连同其他未保存改动一起丢掉。
> 重载后看到的合成图 ≠ 本次的新图。判据见「十一之三」：改完图 `海关监管属性` 必须出现橙字告警，没有橙字就是这一单没改动。

### 步骤 5：补海关监管属性（改图后必做，别找错地方）

图片/标题/属性一变，橙色提示「商品标题、图片、属性已发生变更，请重新补全并提交海关监管属性」出现在
**「基本信息」标签页 → 「商品属性」下方**（不是「合规信息」标签页，去那边找不到，白跑一趟）。

```
scroll { scope:"desktop", x: 960, y: 600, direction:"down", amount:5, by:"line" }   # 滚到海关区
click  { scope:"desktop", x: <去设置>, y: <去设置> }
click  { scope:"desktop", x: <抽屉底部「确认」>, y: … }
```

- 抽屉里两项一般已由 AI 预填：`种类 = 其他人形玩偶`、`适用年龄 = >12岁`，核对无误再点确认
- 成功标志：原位置出现灰色标签 **`已设置 ×`**，橙色警告消失
- 「去设置」的 y 随滚动位置变化，**每次都要重新截图量**（旧记录里出现过 1152/835/838/1401/1692 多个位置）
- 有的商品改图后**不出现橙色告警**、`海关监管属性` 一直是 `已设置 ×`（沿用原 listing 配置）
  → 仍然滚下去截图确认一次，别当成没做
- 若「去设置」旁边既没有橙字、也没有 `已设置`，说明这次改动没触发重校验，可按已完成记录
- **反向判据（2026-10-30 血的教训）**：换完图再看这一块，**既没有橙字、`已设置 ×` 又照旧**，八成是"改动根本没落到页面上"
  （回填没点成、或页面被重载过）。这时不要勾完成，回去看「更多图片」末位有没有**带当天时间戳**的新合成图，
  没有就重做这一次回填。整批 29 项就是这样被误判成"完成"的。

### 步骤 6：回到商品图片这一屏，停

```
scroll { scope:"desktop", x: 960, y: 600, direction:"up", amount:5, by:"line" }
```

交付给用户核对：主图、更多图片、类目、商品视频、营销图、商品属性（品牌/产品类型/适用年龄/高关注化学品）。

## 六、多个商品怎么串行（重要）

**每个商品单独开一个标签页，绝不在原标签页里跳转。**

```
hotkey { scope:"desktop", keys:["ctrl","t"] }     # 新标签页
# 再走步骤 0 的地址栏输入流程
```

原因：改过图/属性的发布页有未保存内容，在**原标签页**跳转必然弹出 Chromium 的
「是否离开网站？你所作的更改可能未保存。」模态框，拦在中间；点「离开」= 放弃上一个商品刚做的全部改动，
点「取消」= 卡住不动。新标签页没有这个包袱，一步绕过。

> ⚠️ 已经弹出来了怎么办：先截图留证，**问用户**再决定。点「离开」= 主动丢弃当前页未保存改动。

## 七、安全闸门（硬规则）

1. **「提交」永远不自己点**。点击前必须拿到用户明确同意，并说明「这会把商品真正发布/更新到线上」。
2. 改动只在页面内存/服务端草稿里，**刷新或关标签有丢失风险**；要收尾就提醒用户点提交，或明确告知未保存。
3. **不碰删除、下架、批量操作**按钮（清重复图这类动作先问用户）。
4. 出现滑块验证 / 账号异常 / 异地登录提示 → 停手，把截图给用户。
5. 真实点击会移动卖家的鼠标。开工前一句话告知；动作之间别乱点，别在同一像素连点两下。
6. `click` / `drag` 返回 `effect:"unverifiable"` —— **动作送达 ≠ 结果达成**，必须自己截图断言。
7. 破坏性动作（离开对话框、删除图、提交）一次一步，等用户点头。
8. **报"完成"必须带判据**：橙字告警出现过 / 更多图片末位有新时间戳合成图 / 主图格换成了新图（截图可指认），
   三者至少给一条。**"看起来是合成图"不算判据** —— 这些商品本来就有上一批的合成主图，
   2026-10-30 就是这样把 29 个没改动的商品报成"全部完成"的。

## 八、常见故障对照表

| 现象 | 原因 | 处理 |
|---|---|---|
| 点了没反应 | 坐标偏了（缩略图/按钮有内边距） | 裁图放大 2 倍量 bbox/颜色，别用肉眼估 |
| 「是否离开网站」模态框 | 在原标签页跳转，而该页有未保存改动 | **不要在原标签跳**；改用 `ctrl+t`。已弹出先问用户 |
| 弹窗出现 `FAIL_SYS_ILLEGAL_ACCESS` | 首次取上传地址失败 | 无视；图片通常已进图库，靠截图确认 |
| 「确认上传」一直是灰的 | 上传其实已成功 | 直接关弹窗继续 |
| 图库里出现两张一样的合成图 | 回填已自动放好一张，又多点了蓝色「确认上传」 | 蓝按钮也不点；已重复的先问用户再清 |
| 编辑器提示「没有识别到包装盒，已用另一张素材填位」 | 原始素材里没有包装图 | 正常兜底，看画布效果可接受就回填 |
| 「回填到商品页」点了没用 | 点到按钮左侧空白 | 取按钮几何中心，裁图重新量 |
| 抠图 6/6 后画布还是空的 | 「智能排版」还在跑（`正在排版…` / `AI 识别中…`） | 再等约 20s 截图判断 |
| `去设置` 点了没反应 | 按钮高约 50px，y 偏 30px 就落空 | 放大裁图量 bbox，点中心 |
| 扩展设置页 `E_PAGE_FILL_FAILED`：图片位已全部占用 | 该商品 6 个图槽都满，回填找不到空位 | 先删一张（问用户）再回填，或看末位是否已多出合成图 |
| 拖拽后顺序没变 | 拖太快 / 落点没进槽位 | 重跑 `drag`，落点取目标缩略图正中 |
| 抠图为 0 且素材为空 | 图片源不可读 | 回商品页确认图库有图，重新进编辑器 |
| **抠图 `6/6 成功 0 失败 6`（全失败）** | **服务端瞬时故障，不是登录/密钥问题**（2026-10-29 实测：账号已连接、服务地址 200） | **关掉编辑器标签，回商品页重新点扩展图标开一次**，第二个 session 立刻 6/6 成功并复用缓存 |
| **拖拽后新图没进第 1 格** | 落点落在第 1 格中心 → 实际插到第 2 格 | 落点取第 1 格**左半边**（1920 口径 x≈315，3840 口径 x≈630） |
| **换了版式模板，画布没变** | 同素材组合命中了「成品图缓存」 | 改 `主体素材` 才会真正重排；或用卡片下「清除本地缓存」再生成 |
| **想选回上一套版式，列表里没有** | 下拉列表只列"其它"选项，当前值不在列表里 | 另选一个模板再生，或撤销（`Ctrl+Z` / 顶栏撤销） |
| **主体被裁到四边 / 红字提示"压住了…的头部"** | 素材本身是特写图，hero/three_pose 都会放大到溢出 | 换 `主体素材`（正面/侧面/背面）+ `包装盒=无`；实在不行接受近景版，别无限试 |
| 页面白屏/转圈 | 网络或编辑器加载慢 | 停 2–3 秒再截一张，别连点 |
| 截出来的图跟我看到的不一样 | 截的是别的窗口/别的 Edge 配置 | 先确认目标窗口在最前，再截 |
| **回填/确认上传后，主图和图库毫无变化，重载后一切照旧** | 上传后又 `ctrl+r` 重载 → 页面内存里的新图被丢弃（2026-10-30 整批 29 项栽在这） | 重做一次回填；之后**绝不重载**，直接拖到主图位，停在标签页等用户提交 |

| **`navurl` 把上一个商品页的未保存改动丢了** | `screen.py navurl` **默认会自动点「离开」**（日志 `leave_dialog … leave_button [2261,455]`），而当前标签有 `beforeunload` 保护 | 一律 `navurl … --no-auto-leave`；发现「是否离开网站?」立即 `hotkey esc`（=取消），别点「离开」 |

| **点击/拖拽/滚轮落到了别的窗口上** | 环境是"人机共用"：卖家切回 DSH GUI 会抢走前台，而 `SendInput` 发给**当前前台** | 每一次 click/drag/wheel 之前都先 `focus Microsoft`（`one_product.py` 的 `click/drag/stage_customs` 已在每步前调用 `focus_edge()`）；卖家正在操作时就先别动 |
| **脚本判断窗口标题全部失败（中文变 `新建标�页`）** | Windows 控制台按 GBK 解 UTF-8，`subprocess` 默认 `errors="ignore"` 把字吃坏 | 所有读输出的地方带 `encoding="utf-8", errors="replace"`（或 `set PYTHONIOENCODING=utf-8`）；标题匹配失败先怀疑编码，不要怀疑窗口 |

## 十一之二、Windows 200% 缩放下"鼠标点了完全没反应"的真凶（2026-10-29）

一次真实误判，排查近一小时，记下来别再犯：

- 现象：`SetCursorPos` 能移动光标、页面悬停态会变，但**任何点击都不生效**；`Ctrl+Tab` 能让页面出现焦点环，`Ctrl+L` 却打不开地址栏。
- 真因：屏幕 **3840×2160 @ 200% 缩放**，而自建 PowerShell 工具是 **DPI-unaware**（`GetProcessDpiAwareness=0`）。于是
  `CopyFromScreen` 只截到屏幕**左上角 1920×1080 那一块**（窗口右半边一直在屏幕上、只是没拍到），
  `SetCursorPos/点击` 的坐标又被系统按 DIP 处理 → "点 A 命中 B"，看起来就是"点了没反应"。
- 解法：进程先 `SetProcessDpiAwarenessContext(PER_MONITOR_AWARE_V2)`；之后 `GetSystemMetrics = 3840×2160`、截图/点击/拖拽全在物理像素空间。
  官方 `cua_driver_native__get_screen_size` 也返回 `3840x2160 pixels @ 2x`，可用来对账。
- **坐标纪律**：`get_desktop_state` 的预览图不是物理像素（标注 ×1.41，实测 ×≈2.16）；
  `read_image` 还会再降采样（1920×1080 图显示成 1600×900）。→ 坐标一律用**全分辨率 1:1 裁剪图**量（裁剪宽 ≤1400 时不降采样）。

## 十一之四、2026-10-31「人机共用一台机器」的脚本安全化改造（必读）

卖家会一边看 DSH GUI 一边让我在后台跑浏览器，于是**前台窗口随时会被抢走**。这一轮踩了三个坑，全部改到
`scripts\one_product.py` 里了：

1. **`ctrl+t` 可能发给别的窗口** → 先 `screen.py focus Microsoft`，`ctrl+t` 后**读窗口标题**确认出现
   「新建标签页」，三次都失败就 `ABORT`，绝不带着旧标签继续导航。
2. **`screen.py navurl` 默认会替你点「离开」**（日志里 `leave_dialog … leave_button [2261,455] … dismissed:false`）——
   一旦它点中，当前商品页未保存的改动就被丢弃。→ 调用时永远加 `--no-auto-leave`；
   真弹出「是否离开网站?」时用 `hotkey esc`（取消），**不要点「离开」，也不要点 `取消` 的坐标**（点坐标曾落空，ESC 稳）。
3. **中文标题/输出乱码**：Windows 控制台按 GBK 解 UTF-8，`subprocess(text=True)` 默认 `errors="ignore"` 会把
   「新建标签页」吃成 `新建标�页`，导致所有字符串判断静默失败。→ 读子进程输出一律
   `encoding="utf-8", errors="replace"`，脚本运行时 `set PYTHONIOENCODING=utf-8`。
4. **每一步动作前抢前台**：`click()` / `drag()` / `stage_customs()` 内部先调 `focus_edge()`（`screen.py focus Microsoft`
   并校验 `"foreground": true`），否则 `SendInput` 会点到卖家正在用的 DSH 窗口上。
